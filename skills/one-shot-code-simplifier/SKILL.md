# One-shot Code Simplifier｜一次性等价代码精简重构技能

## 核心目标

在**运行行为、输入输出、业务逻辑完全等价无变更**的硬性约束下，遵循「先全局分析→再方案规划→最后批量重构」流程，一次性完成目标代码/项目精简优化。
核心收益：消除冗余代码、降低维护成本、提升可读性、增强逻辑复用；**同步落实模块化设计，切割职责边界、降低模块间耦合度**；全程拒绝无方案、碎片化零散修改，所有改动有据可依。

## 标准重构执行流程

1. **全局结构分析**
   梳理项目目录分层、模块职责、依赖关系、数据流、重复逻辑分布、历史兼容冗余范围；重点识别高耦合代码、跨模块硬依赖、职责混杂的大文件，定位臃肿文件/超长函数/深层嵌套/重复分支。
2. **重构方案规划**
   基于分析结果输出精简+解耦优化方案：划分独立职责模块、消除硬耦合依赖、统一基建逻辑、抽离复用单元、拆分庞杂模块、清理无效代码、简化复杂判断，严格划定改动边界，确保无功能风险。
3. **批量落地改造（按需选用，不超规划范围）**

- 安全清理：未执行死代码、无效导入、未使用变量、不可达分支、废弃注释、过时版本兼容代码
- 消除重复：合并同质化分支、重复业务实现、重复数据转换/校验逻辑
- 逻辑抽离：将语义统一的重复逻辑封装为 helper / hook / component / service / adapter，命名贴合业务语义
- **模块化拆分（新增）**
  按单一职责切割大模块、大组件，拆分职责混杂文件；区分通用底层模块、业务模块、适配层模块，明确各模块边界
- **解耦优化（新增）**
  移除模块间硬编码导入、跨层直接调用；通过抽象接口、适配层、参数注入、事件派发等弱耦合方式替代紧耦合调用；隔离外部依赖与业务代码
- 简化层级：扁平化多层嵌套、重构复杂多分支条件判断，提升阅读流畅度
- 统一基建：标准化参数校验、状态映射、数据转换、公共渲染等底层通用逻辑

## 强制约束 & 注意事项

1. **功能等价红线**：所有重构前后接口、返回值、业务分支、异常行为必须完全一致，禁止隐性逻辑变更、性能逻辑删减、业务规则修改。
2. **兼容代码处理规则**
   区分「永久生效新兼容逻辑」与「仅适配旧数据、不再执行的废弃兼容代码」：
   - 废弃、无运行场景的旧数据兼容代码直接清除；
   - 多版本兼容冲突时，仅保留适配当前业务版本的最新兼容实现，彻底移除过时兼容分支。
3. **模块化与耦合约束**
   - 严格遵循单一职责原则，一个模块只负责一类能力，禁止业务逻辑、通用工具、第三方适配代码混杂在同一文件；
   - 减少跨层级直接导入调用，上层业务仅依赖抽象/适配层，不直接引用底层实现细节；
   - 避免循环依赖、双向强耦合，重构时梳理单向清晰的依赖流向；
   - 第三方SDK、外部接口统一封装独立适配模块，业务代码不直接耦合外部API。
4. **改动边界约束**
   严格遵循前置规划方案，不擅自扩大修改范围；不新增业务能力、不删减正常校验逻辑、不修改外部接口出入参结构。
5. **输出规范**
   重构完成后附带精简说明：改动点、冗余消除位置、抽离复用单元、模块化拆分方案、解耦优化点清单，证明行为无变化。
