# Video

本地视频抽帧：把视频里的几个时刻抽成 JPEG，交给模型逐张看。没有「原生视频输入」这个通用能力，Gemini 的 video 本质上也是服务端按秒抽帧，所以这里不做协议层特判——**抽帧落盘 → 图片走已有的图片链路**。

**它不是常驻工具**：`video_frames` 的 schema 每轮都会随请求发送，而这个能力并不常用。现在能力挂在 `/plugin/video/api` 上，清单用 `uriApis` 声明文档地址；用户从输入框的 `/` 浮层里挑「video」时只插入这个 URI，模型需要时再读文档、调接口。会话里零常驻。

依赖本机的 `ffmpeg` / `ffprobe`（缺失时上报健康状态并给出可行动的报错）。可寻址的单位是**时间**而不是帧序号：下一轮的模型看不到上一轮读过的图片，`at: ["1:03.5"]` 才是自洽的引用方式。

## 机读接口

地址：`/plugin/video/api`（应用现有端口的同源路径；`GET` 根地址由宿主回文档：`description` / `guide` / `endpoints`）。

| 方法   | 路径      | 作用                                         |
| ------ | --------- | -------------------------------------------- |
| `POST` | `/frames` | 按时间点抽帧，返回每帧的本地绝对路径与时间点 |

请求体：`{ source, at?, count?, start?, end?, scale? }`。

- `source`（必填）：本地绝对路径、`~/` 开头的路径，或 `http(s)` 直链。相对路径按应用进程的工作目录解析——接口拿不到会话 cwd，所以写法上优先绝对路径。
- `at`：精确点名的时刻，接受 `90`（秒）、`1:03.5`、`01:02:03`；最多 8 个。给了它就忽略 `count` / `start` / `end`。
- `count`：不给 `at` 时抽几帧，默认 4、上限 12。给了非法值（0、负数、非数字）返回 400，不会悄悄按默认值办。
- `start` / `end`：只缩小采样范围（长录屏看某 10 分钟）。
- `scale`：帧的长边像素，默认取插件设置（1024），范围 512–1568。

响应 `data`：

```json
{
  "video": {
    "source": "/abs/clip.mov",
    "durationSeconds": 62.4,
    "width": 1920,
    "height": 1080,
    "fps": 30,
    "hasAudio": false
  },
  "text": "Video: …\nFrames (2) saved as local JPEG files:\n  0:03.0  /…/frames/<指纹>/1024-3000.jpg …",
  "frames": [{ "seconds": 3, "at": "0:03.0", "path": "/…/frames/<指纹>/1024-3000.jpg", "bytes": 41234 }]
}
```

`text` 与 `frames` 是同一份信息的两种形态：`text` 给模型直接读，`frames` 给程序用。**图片不在响应里**——响应必须是可 JSON 序列化的值。

### 30 秒与短视频限制

- 单次请求 **30 秒上限**：宿主到点中止并返回 `504 timeout`，插件侧尊重 `request.signal`，取消与超时原样上抛（不包装成 400/500）。
- 只适合**本地短视频，或已经缓存过的视频**。同一个视频的同一批时刻第二次调用直接命中已抽好的帧，不再解码（元信息仍要探测一次）。
- 远程 `http(s)` 直链会先把整段视频下载到本机再抽帧，几百 MB 的片子一定超时。**长视频与远程视频请先把文件下载到本地，再把本地路径传给 `source`。**
- `start` / `end` 只是缩小采样范围，不能突破上面两条：扫描一段 10 分钟仍然要解码那 10 分钟。

### 两步流程：先抽帧，再 read_image

1. `POST /frames {source}` 拿概览（默认 4 帧）与时长、分辨率、有无音轨。
2. 对每个 `frames[i].path` 调内置 `read_image` 逐张看——**一次 3–6 张**。每帧都会作为图片进入上下文并在后续轮次重复发送，一次看十几张既慢又贵。
3. 要精看某几秒时再 `POST /frames {source, at:["4:50.5"]}`，然后同样用 `read_image` 看新路径。

引用某一帧时说时间点（`4:50.5`），不要说「第 3 帧」：下一轮谁都拿不到序号到时间的映射。音频不会被转写，问「说了什么」时先说明这一点。

### 缓存位置与容量

- 帧：`$MICA_HOME/plugin-data/video/frames/<视频指纹>/<长边>-<毫秒>.jpg`。指纹是「真实路径 + 大小 + mtime」，视频改过就换一个目录，不会读到旧帧；换长边也不会命中尺寸不对的旧图。
- 下载的远程视频：`$MICA_HOME/plugin-data/video/sources/`。
- 两者共用插件设置里的「缓存上限」（默认 512MB），超过时从最旧的开始删；一小时内下载的 source 不动（可能正被 ffmpeg 读着）。缓存会被淘汰，不保证第二次仍在。

## 实现

| 文件                    | 作用                                                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `extract.ts`            | 流水线：source 解析 / 下载 → ffprobe → 采样计划（场景取样 + 兜底）→ 落盘 → 去重 → 摘要。不认识 `MicaTool`，只给路径与说明 |
| `api.ts`                | `/plugin/video/api` 的端点表、`guide` 与 `POST /frames` 处理：参数校验 + 错误面（400 / 503 / 504 / 500）                  |
| `plan.ts` / `scenes.ts` | 采样计划：`at` / `count` / `start` / `end` 的规则，以及按画面变化取样（整片降采样求差，静止画面只给 1–2 帧）              |
| `frames.ts`             | 帧与下载源的缓存、落盘、容量淘汰                                                                                          |
| `ffmpeg.ts`             | 找到 ffmpeg / ffprobe、读元信息、抽一帧、扫描帧差                                                                         |
| `index.ts`              | 会话侧只有设置、状态、健康检查与 ffmpeg 预热（不再注册工具）                                                              |

## 设置

| 键             | 默认 | 说明                                                                                             |
| -------------- | ---- | ------------------------------------------------------------------------------------------------ |
| `ffmpegPath`   | 空   | 留空则依次查找 PATH、`/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`；ffprobe 默认取同目录那个 |
| `maxEdge`      | 1024 | 每帧的长边像素。调大能看清小字，但每帧体积与 token 成倍上涨                                      |
| `cacheLimitMb` | 512  | 帧与下载源共用的磁盘上限                                                                         |
