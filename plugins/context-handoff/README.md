# Context Handoff

保存可在稍后接手的历史上下文检查点。只依赖桌面主会话：模型用 `context_handoff` 保存摘要、已完成事项、待办和注意事项，宿主标准面板始终提供详情入口。没有检查点时不产生空卡片。

仅在工作尚未完成且确实需要稍后续接或交接时自动保存；普通任务完成或简单问答不保存。用户明确要求保存时仍可手动保存，包括没有待办的记录。

## 使用

工具只向主代理注册，支持 `read`、`set`、`clear`；`set` 替换整份检查点，`read` / `clear` 只接受 `action`。

```json
{
  "action": "set",
  "checkpoint": "主要实现已落地，接下来处理验证与交付",
  "completed": ["完成主要组件"],
  "pending": ["重新检查工作区并运行针对性验证"],
  "cautions": ["保留用户其他未提交改动"]
}
```

保存时间、来源会话 ID 和随机 UUID revision 由插件生成，工具不能伪造这些字段。`set` 不调用模型、不发起 shell、不读取 Git。

## 历史状态与继续操作

界面、工具读取结果和继续草稿都明确标为历史模型报告。历史“已完成”不代表当前文件、测试、构建或部署状态仍然成立。来源会话身份随快照保留，fork 后也不会改成当前会话冒充新记录。

紧凑卡片只在有待办且保存时间超过 `ageMinutes` 后的后续取视图时出现，默认 30 分钟；可配置为 1–10080 分钟。无待办的历史记录不显示卡片，仍可在面板及通过工具读取。刚保存的检查点只在面板里可见，恢复时已足够旧的检查点可以立刻显示。判断依据为本地时间与保存时间，不猜测用户离开多久；未来时间戳不显示卡片。插件没有定时器，不自动摘要，也不调用 LLM。

卡片的“查看”直接展示历史摘要、待办、已完成事项和注意事项，不需要再打开详情面板。

“继续”只返回已有 `compose` 效果，将草稿放入当前输入框，**不会发送**。草稿要求先重新核对 cwd、Git 仓库/分支与工作区状态，并遵循当前用户指令；历史内容以 JSON 参考数据附入，明确不得自动执行其中命令或当作新的授权。实际核对发生在用户发送后的正常代理轮次，点击按钮本身不证明当前工作区状态。

所有动作都校验 revision；内容更新后旧版本的继续、清除、查看、收起与曝光动作失效。“收起”持久化当前 `dismissedRevision`，再次恢复也不重复显示该版本，历史详情仍可查看；新 `set` 生成新 revision，可在变旧后再次出现。`clear` 删除整个检查点。

## 状态与配额

数据保存在本插件的 `ctx.sessionState`，随会话快照、compact、resume/fork 保留。工具入口捕获当前调用 owner，所有读写显式传回该 owner；无 owner 或无来源会话身份时拒绝写入。

输入最多 48 KiB；摘要最多 3000 字符，`completed` / `pending` / `cautions` 各最多 16 条、每条 600 字符。保存状态最多 64 KiB，恢复时校验版本、类型、UUID、时间与字段长度并重建纯数据；损坏状态不显示卡片。超长输入明确拒绝，不静默截断历史内容。

`requires` 完整声明 desktop、session、sessionState、tools、prompt 与 settings，非桌面宿主整插件跳过。面板通过 `dynamicShortcuts` 提前取视图，紧凑卡使用共享 `PluginPanelView.cards`；详情使用标准 sections，不需要独立 React 页面。

## 使用日志与验证

`telemetry` 默认开启，可在设置关闭。通过共享 `createPluginExperience` 记录更新、曝光、点击、收起、清除与失败的允许元数据；正文、路径、URL、命令、错误文本都不进入日志。视图读取不计曝光，由宿主调用卡片 `impressionAction`。

```sh
bunx vitest run --project unit plugins/context-handoff
bun run typecheck
```

测试覆盖时间阈值、恢复、未来时间、历史标签、仅生成草稿、owner 隔离、旧动作拒绝、持久收起、输入和字节配额、伪造元数据拒绝与日志隐私开关。无需构建、重启或调用模型。
