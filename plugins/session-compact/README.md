# 会话压缩

主会话区右键菜单里的两条手动入口（清单里标了 `surface: "chat"`：压缩的是你正看着的这段
历史，侧栏会话行不放这两项）。模型配置变化后，下一次发送会在写入用户输入前自动快速压缩；
不发送就不会触发。只在支持该钩子的桌面会话宿主生效，没有阈值或定时触发。

| 菜单项   | 做什么                                                                             | 代价            |
| -------- | ---------------------------------------------------------------------------------- | --------------- |
| 快速压缩 | 把历史里的工具过程聚合成一条占位调用（说明里写明每种工具调了几次），思考与图片丢掉   | 本地操作，毫秒级 |
| 模型压缩 | 把用户与助手的对话交给模型写一段 checkpoint 摘要，旧历史折成摘要加最近几轮           | 一次模型请求    |

两条都通过 `ctx.agent.compactIdleHistory` 压缩并保存当前会话记录，紧接着发出的请求按压小的
历史发送，`conversationMessages` 同步当前压缩结果。对话区完整展示当前持久化记录：模型压缩
后旧历史会变成摘要加最近几轮，重开会话也读取这份记录，不另存一份不随压缩变化的原始展示历史。
模型配置变化后的轮前 `compactHistory({ mode: 'quick' })` 同样落盘当前压缩结果并同步展示。

## 快速压缩只动工具过程

压缩区里的工具调用与结果合成**一条占位调用 + 一条结果**：调用名是其中出现最多的那个，
说明形如 `[Mica compact] Placeholder for 42 collapsed tool calls (not a real result): read_file × 18, bash × 12…`，
思考（Responses 的 reasoning 条目、Chat 的 `reasoning_content`）丢掉，图片与文档块换成占位
文本。用户与助手的正文原样保留、顺序不变，也不合并轮次。

代价是这一区的工具时序只剩计数，不能再逐条重放：要细节就重新读文件、重跑命令。连续点几次
是幂等的——新计数会并进同一条说明；没有可清理的内容时返回「没有可清理的工具结果」。

## 模型压缩只把对话交给模型

摘要请求里只有用户说的是什么、助手答了什么（以及上一次压缩留下的 checkpoint 摘要）。
工具调用、工具结果、思考过程都不进摘要输入：它们占九成篇幅，却几乎不进摘要结论。
内核的 `CompactionService` 用 `summaryInput: 'dialogue'` 生成这份正文，分段、预算与截断
仍归它管。

摘要请求走清单里的 `llm`：默认复用当前会话模型，也可以在插件设置里换成更便宜的接口
（失败会自动降级回会话模型）。

## 什么时候用哪个

- 任务跑了一大段、上下文里堆着几十万 token 的工具输出，但对话本身还有用：**快速压缩**。
- 上下文已经被旧任务塞满、想把它收成一段能接得上的摘要：**模型压缩**。

## 实现要点

- 菜单项来自清单（`desktop.sessionMenu`），处理器来自 `ctx.desktop.sessionMenu()`：
  右键要立刻画出菜单，不能为了知道有没有菜单项去冷启动一个 app-server。两项各自
  声明了图标（`eraser` / `sparkles`）：共用插件图标时，菜单上分不出哪一行是哪件事；
  也都写了 `surface: "chat"`，只出现在主会话区的右键菜单里。
- 会话正忙（这一轮在跑、另一个进程持有 turn lease）时宿主返回 `busy`，插件提示
  「等这一轮结束再压」，不会排队、更不会插进正在跑的请求。
- 菜单动作只有一句 `message` 能回给用户，所以失败也折成一句话（「模型压缩失败：…」），
  不抛异常——抛出去页面只会显示一句更含糊的错误。
- 没有阈值、计数与空闲提醒：清单里没有 `settings`，除了 `llm` 面板（选摘要模型）之外
  不存任何配置。切换后的快速压缩同样改写当前会话记录，界面随持久化结果同步变化。
