# Quick Buttons

输入框上方那一排「点一下就走」的按钮：模型用 `quick_buttons` 工具建，用户点，插件把这一下翻译成一件具体的事。

## 它做什么

- **按钮属于当前会话**：存在会话快照的 `pluginState['quick-buttons']`，切到别的对话就看不见、resume / fork 带得回来、压缩改不到它。任务变了就换掉这一排，别指望它当一个待办清单用。
- 工具创建的按钮记录来源及创建 / 更新时间（Unix 毫秒）。超过 7 天未更新的模型按钮标记为「可能过时」；面板的「清理可能过时」或工具的 `clear_stale` 只在显式调用时清理这些按钮，手动按钮与时间未知的历史按钮不受影响。时间只是提醒，不代表内容确实失效。
- **五个落点**：不直接运行命令，但打开网页或启动新会话仍可能产生后续操作，具体权限由宿主控制。

  | kind      | 点一下                           | 交给宿主的回包              |
  | --------- | -------------------------------- | --------------------------- |
  | `open`    | 打开一个网址                     | `openExternal` 或受控浏览器 |
  | `compose` | 把一段话放进输入框（**不发送**） | `compose`                   |
  | `session` | 开一个新会话跑一段提示词         | `newSession`                |
  | `path`    | 在应用里打开一个文件或目录       | `openPath`                  |
  | `dialog`  | 弹出一个说明 / 清单 / 几个做法   | `dialog`                    |

- `open` 默认走**受控浏览器**（桌面端主进程里那个 agent 还能继续操作的窗口），窗口归属当前会话，所以顶栏的浏览器图标上看得到它；`target: "external"` 才交给系统浏览器。受控浏览器不可用时自动退回系统浏览器，并在按钮旁边说明。
- **一排最多 6 个**：输入框上方的位置有限，按钮多了用户得先读一排字才找得到要点的那个，比自己做还慢。超出的由工具明确拒绝，让模型自己挑。
- **外观只声明意图**：`style: { icon, color, shape, iconOnly }`——图标取应用那张 lucide 表
  （`globe` / `external` / `search` / `zap` / `list-checks` …），颜色取 `accent`（点这个）/
  `danger`（会改东西）/ `success` / `warn`，形状取 `soft` / `plain`，`iconOnly` 只画图标。
  色值来自宿主主题令牌，明暗两套各自成立——插件写死颜色必然有一边读不清，所以这里只能选，不能写。
  认不出的取值当没写（不猜一个差不多的颜色）。

- **弹窗 `dialog`**：一段说明 + 可选的两列清单 + 最多三颗底部按钮，全部由宿主用已有的
  `ModalShell` / 表格 / `Button` 画，插件只给内容：

  ```json
  {
    "label": "看候选",
    "kind": "dialog",
    "style": { "icon": "list-checks", "shape": "soft" },
    "dialog": {
      "title": "两条候选",
      "markdown": "- 需求单 A（昨天）\n- 需求单 B（上周）",
      "items": [{ "label": "需求单 A", "value": "昨天", "url": "https://example.com/a" }],
      "note": "选一个继续",
      "actions": [
        { "label": "打开 A", "kind": "open", "url": "https://example.com/a", "tone": "primary" },
        { "label": "追问", "kind": "compose", "text": "按 A 继续说" }
      ]
    }
  }
  ```

  弹窗动作和快捷条点击都携带按钮内容指纹；插件先核对当前内容，再执行对应动作（`open` 仍默认受控浏览器）。
  按钮删除、内容更新或动作重排后，旧界面点击会提示重新打开，不会执行新内容。弹窗里不能再套弹窗。

- **不给模型留后门**：按钮只表达「用户要做的下一件事」，不承载删除、提交、发布这类会改东西的操作——点一下就跑脚本的按钮，是钓鱼最省事的样子。

## 面板

面板（`desktop.panel`）是这一排的维护界面：看一眼现有按钮、删掉一个、手动加一个（不是每件事都值得开口让模型做）。表单里填的三个字段就是一枚按钮的全部——名称、点一下是什么、内容（网址 / 一句话 / 提示词 / 路径，相对路径按会话目录补全）。

面板**没有把按钮写进清单**，而是声明 `dynamicShortcuts: true`，按钮由 `view()` 在运行期给出：清单是磁盘上的静态文件，写不出「这一轮需要哪几个按钮」。视图给的按钮与清单里声明的共用同一套渲染，`shortcutStates` 也照样按 id 生效。

## CLI

工具在所有宿主里都注册——`mica exec` / TUI 里按钮没有落点，但工具结果会把每个按钮的地址、文本、路径摊平成可读的行：

```
当前会话有 2 个快捷按钮。这个宿主里没有输入框上方的按钮，直接用下面的内容：
- 打开需求单 · 打开网页 → https://example.com/1（受控浏览器）
- 追问 · 放进输入框 → 再查一下日志
```

所以 `plugin.json` 的 `requires` 里**没有** `desktop`：插件在 TUI 里照常装配，只是没有面板，那段 `prompt` 也不渲染（不鼓励模型在没有落点的地方建按钮）。

## 存的东西

| 位置                                    | 内容                                        |
| --------------------------------------- | ------------------------------------------- |
| 会话快照 `pluginState['quick-buttons']` | `{ version: 1, buttons: [...] }`，最多 6 条 |

按钮 id 是小写 slug（`open-demand`、`button-1`），它是页面上的 React key 与 `shortcutStates` 的键；点击时回传的 key 另外带内容指纹。历史数据里 id 不合法的条目在读取时就被丢掉，宁可少一枚按钮也不要一枚点不动的。

## 文件

| 文件                  | 作用                                                                                |
| --------------------- | ----------------------------------------------------------------------------------- |
| `plugin.json`         | 清单：`requires` 与 `desktop.panel`（`dynamicShortcuts`）                           |
| `index.ts`            | 入口：工具 + 面板 + prompt 段落                                                     |
| `buttons.ts`          | 数据模型：校验、归一化、限额、给模型看的那几行                                      |
| `QuickButtonsTool.ts` | `quick_buttons` 工具（`list` / `set` / `add` / `remove` / `clear` / `clear_stale`） |
| `panel.ts`            | 面板视图与动作：点按钮、手动增删                                                    |
| `browser.ts`          | 受控浏览器：`POST $MICA_BROWSER_URL/browser/browsers`                               |
| `prompt.ts`           | 什么时候该建按钮（只在桌面宿主里渲染）                                              |
