# Web Search

`web_search` 工具（SearXNG）与配套的联网查证指引。

## 为什么在插件里

工具、地址配置、以及「什么时候该联网、怎么读一手资料」这三件事是同一条链路：
只把工具挪走、把指引留在 base prompt 里，插件停用后模型仍会照着提示词去调一个不存在的工具。
所以这里一起搬：`requires: ["tools", "prompt", "settings"]`，停用即三者同时消失。

`web_fetch`（抓取并转换 HTML）仍在内核——它是通用能力，不依赖任何外部实例。

## 配置

配置页 Plugins → Web Search，或 `$MICA_HOME/plugin-settings/web-search.json`。

| 项       | 默认 | 说明                                                       |
| -------- | ---- | ---------------------------------------------------------- |
| 地址     | 空   | SearXNG 实例地址，必须开启 JSON format；留空则按下一节解析 |
| 默认条数 | 5    | 模型没有显式传 `count` 时返回几条，范围 1–20               |

地址解析优先级：插件设置 → `SEARXNG_URL` 环境变量 → `http://127.0.0.1:8080`。
保留环境变量是因为 CI / 容器里换实例比改配置文件方便。
地址与默认条数在每次调用时读取，设置保存后下一次搜索即生效。

## 失败怎么暴露

- 配置不完整：健康状态直接是「待配置」，并写清哪一项不对；工具仍然注册，模型调用时给出明确失败原因，
  而不是让工具凭空消失。
- 请求失败（实例没开、格式没开、超时）：`ctx.health.report({ level: 'error' })` 写进插件健康状态，
  配置页能看到「出错」与原因，日志里同时留一条。
- 停止当前请求会立即取消搜索，不记成实例故障；实例恢复并成功返回后，健康状态随之恢复。

## 结果处理

按 `count` 本地截断（最多 20 条），结果与附加信息一起缓存 5 分钟；缓存最多 500 条、总计 4 MiB、单条 256 KiB（按字符串 UTF-16 大小估算），超大结果仍可返回但不缓存。请求总预算 20 秒，响应头后停滞或响应超过 2 MiB 时也会取消读取。`web_fetch` 负责打开页面并转成 Markdown。
