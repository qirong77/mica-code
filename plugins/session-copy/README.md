# Copy Session

会话右键菜单里的「复制会话 Markdown」：把一条会话的核心信息拼成 Markdown 放进剪贴板，
粘到工单、文档或另一条会话里就能直接读。

```md
# 修一下会话列表的排序

- 会话 ID：3f9c1b0e-…
- 路径：/Users/me/work/mica-code
- 模型：OpenRouter / moonshotai/kimi-k3
- 角色：需求开发
- 对话条数：12

## 对话

### 1. 用户

侧栏按更新时间排序时，子会话会跑到父会话上面。

### 2. 助手

看 `session-nesting.js` 的 `nestSessions`：它只改渲染顺序……
```

## 复制什么、不复制什么

| 内容                           | 是否复制 | 原因                                           |
| ------------------------------ | -------- | ---------------------------------------------- |
| 标题、会话 ID、路径、模型      | 是       | 贴出去第一件事就是「这是哪条会话、在哪个目录」 |
| 角色                           | 是       | 同一句话在不同角色下的含义不同                 |
| 用户与助手的正文               | 是       | 这就是这次对话本身                             |
| 工具调用与工具结果             | 否       | 篇幅占九成，读者要的是结论而不是过程           |
| 思考过程                       | 否       | 同上，而且通常是模型写给自己的草稿             |
| notice（重试、失败、命令结果） | 否       | 属于运行日志，不是对话                         |
| 图片                           | 占位     | 写成 `[图片]`：本地路径贴出去对方也读不到      |

## 为什么不做成模型总结

复制是一个**应当立刻完成、每次都一样**的动作。让模型参与意味着：等一次请求、花一次额度、
同一份会话两次复制出两段不同的文本。所以这里只有确定性的拼装
（`plugins/session-copy/markdown.ts`），没有任何 `ctx.llm` 调用。

## 实现要点

- 内容在会话的常驻宿主（`mica app-server`）里拼：只有那个进程里有会话快照。
- 剪贴板由页面写：插件进程没有剪贴板，也不该为三个平台各调一次系统命令。插件回
  `{ copyText, message }`，页面把 `copyText` 写进去、把 `message` 显示出来。
- 菜单项来自清单（`desktop.sessionMenu`），处理器来自 `ctx.desktop.sessionMenu()`：
  右键要立刻画出菜单，不能为了知道有没有菜单项去冷启动一个 app-server。
- 会话没有对话时仍然复制路径与模型，提示改成「已复制路径与模型信息（还没有对话内容）」。
