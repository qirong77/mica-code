# schedule

这台机器上有一份**本地排期**，桌面端侧栏 `Schedule` 打开就是它（一个甘特图）。它不是任何
聊天工具的附属数据，也不从聊天记录里抓：内容全部由用户和你在对话里维护。

结构只有两层：

- **计划**：一行，一个项目 / 一个主题 / 一件要推进的事；
- **阶段**：那一行里的彩色条，有名字和起止日期（含首尾两天）。

改名、改期、加条、删条都靠 `schedule` 工具完成，**不要**去 `$MICA_HOME/plugin-data/schedule/`
下改 JSON——用户可能正打开着页面，工具写盘与页面写盘共用一把锁，手改文件会绕过它。

## 怎么用

1. **先读**：`schedule`，`operation: "list"`。回包里每条阶段都带 `stage_id`，每个计划带
   `plan_id`，第一行是今天的日期。没有这一步就不要猜 id。
2. **再改**：一次一条操作。
   - `add_plan`：新建计划（`name`，可选 `note`）；
   - `update_plan`：改名或改备注（`plan_id` + `name` / `note`）；
   - `delete_plan`：删掉计划和它下面所有阶段（用户说「这个不做了」「删掉那个计划」时）；
   - `add_stage`：给计划加一条阶段（`plan_id` + `name` + `start`，`end` 省略就是同一天）；
   - `update_stage`：改名或改期（`stage_id` + 要改的字段）；
   - `delete_stage`：删掉一条阶段。
3. **回报一句**：工具已经回了「已把「联调」改成 2026-11-03 → 2026-11-09（7 天）」这样的
   话，把这一句转述给用户就行，不要整份贴回去——除非他就是要看全貌。

## 规则

- 日期一律 `YYYY-MM-DD`，只写日期不带时分；`end` 含当天（`2026-11-09 → 2026-11-09` 是 1 天）。
- 用户说得模糊时按常识落到具体日期：「下周联调」→ 从下周一算起一周；「月底上线」→ 那个月
  最后一天。落完把具体日期说出来，让人有机会纠。
- 阶段名自由（`开发` / `联调` / `测试` / `上线` / `灰度` / `客户验收`…），页面按名字上色，
  所以沿用用户自己说过的那套词，别改写成别的说法。
- 新建前先看有没有同名计划：同名说明是同一个项目，往里加阶段，而不是再开一行。
- 阶段已经过去的不要去「清理」——排期保留了历史，页面靠它看进度。
- 一次改多条时逐条调用（每次一个 `stage_id`），比一次塞一大坨更不容易改错位置；改完再
  `list` 一次核对，把改动逐条念给用户。
- 工具报「这个计划已经不在了 / 这条阶段已经不在了」= 用户（或另一个窗口）刚删掉，重新
  `list` 再判断要不要加回去，不要凭旧 id 硬写。

## 用户提请求的常见形态

- 「看下排期」：`list`，然后按「正在进行 → 接下来 → 已结束」的顺序挑几条讲，不要念完整份。
- 「加一个 X 项目，11 月开发、12 月上线」：`add_plan`，再两条 `add_stage`。
- 「测试挪到验收之后」：`list` 拿日期，`update_stage` 改起止，必要时连验收一起挪。
- 「这个不做了」：`delete_plan`（先确认是哪个计划——同名时问一句）。
