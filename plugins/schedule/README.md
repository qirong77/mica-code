# Schedule

把 D-Chat 群公告里的开发排期整理成一张甘特图：侧栏一行 `Schedule` 入口，点开是整页时间线——**一个群一行**，行里的彩色条是它的开发 / 联调 / 测试 / 上线等阶段。

## 数据从哪来

D-Chat 没有「读群公告」的接口：公告**只在被修改时**作为一条 `subtype=announcement` 的消息进入
消息流。所以「当前公告」只能这么拿：

1. `dws chat +dump-chats` 拿群列表（名字、最近活跃时间）；
2. 对每个群 `dws message +dump-by-chat --from … --to …` 导出窗口内的消息；
3. 取最后一条 `announcement`，用 `parse.ts` 把里面的排期读成阶段。

代价是**一个群一次导出**（实测 3～4 秒），所以整理是慢操作：结果整份写进
`$MICA_HOME/plugin-data/schedule/data.json`，页面只读这份缓存。窗口上限 30 天来自 dws 自身
（`time range exceeds 30 days`），因此 **30 天内没改过的公告读不到**——这是数据源的边界，
不是插件的 bug。

## 排期怎么认

`parse.ts` 只认两类稳定信号：一个已知阶段词（开发 / 联调 / 提测 / case 评审 / 测试 / 验收 /
走查 / 上线 / showcase / 评审）+ 同一段里至少一个 `M.D` 或 `M-D` 日期。先后顺序不假设：

- `10.15～10.21开发，10.22～10.26联调，测试：10.28-10.30，走查+上线：11.02`
- `开发：10.27-11.02，联调：11.03-11.09，测试：11.10~11.13，走查上线：11.16`
- `开发：10.30、11.2，联调&提测：11.3`

「走查上线」「联调&提测」这类合写按 `+ & 和 及` 拆开，算两个阶段落在同一天。认不出阶段词的
公告返回空数组——群里没有排期是正常情况，不是错误。年份按参考日期补：跨年那两种写法
（12 月发 1.5、1 月发 12.28）各挪一年，其余（包括已经过去的旧日期）保持原年。

## 页面怎么用

横向是日期、纵向是群；一条是一段排期，颜色区分阶段，条上放不下字时不画字，点一下在底部
读出这段的原话（阶段、起止、共几天、公告作者与时间）。

- **滚轮就是缩放**（锚在光标，不跳视野），Shift + 滚轮或触控板横滑是平移；纵向少了滚轮，
  行多了用滚动条——一次滚轮只改一样，手才不会打架。
- 日 / 周 / 月换刻度；「今天」把视野拉回当天。
- 顶部那排阶段胶囊点一下可以隐藏该阶段，用来只看「开发 + 上线」这类两条线。
- 右上角「刷新」触发一次重新整理，跑的时候转圈并标「整理中」。

`gantt.ts` 负责纯几何（行、泳道、日期轴、缩放锚点换算），页面只负责画；缩放的锚点算法是
「缩放前光标落在第几天，缩放后还是那一天」，不是简单地按比例改滚动条。

## 什么时候整理

- **手动**：页面右上角「刷新」、配置页插件详情里的「重新整理排期」。两者都执行
  `mica plugin-action --plugin schedule --action refresh`（一次性进程，不需要会话）。
- **自动**：会话进程里每 10 分钟醒一次，数据比 `autoRefreshHours` 旧才真去整理
  （0 = 关掉）。多个窗口同时开会抢同一个锁文件 `plugin-data/schedule/refresh.lock`，
  只跑一遍。

群多时一轮可能跑不完：并发 4、整轮预算 100 秒（手动）/ 240 秒（自动），超了就把已经扫到的
先写出来，页面左上角标「没扫全」。

## 设置

| 设置 | 作用 |
| --- | --- |
| `dwsPath` | D-Chat 命令行的路径；留空先找 SmartWork 自带的 `dws-unix.sh`，再找 PATH 上的 `dws` |
| `groups` | 看哪些群，一行一个群名或群 id；留空 = 最近 7 天有消息的全部群 |
| `days` | 回看几天内的公告（1–30，上限来自 dws） |
| `autoRefreshHours` | 自动整理间隔；0 只在手动时整理 |

## 失败怎么体现

- 找不到 dws、`dws` 跑不起来：插件健康状态报 `error`，页面照旧显示上一次的结果；
- 某个群没扫成（名字写错、没权限）：记进 `data.json` 的 `errors`，页面左上角显示「N 个群没扫成」，
  悬停看原因；
- 公告里没有排期：正常情况，不进 `errors`。

## 边界

- 只读，不发消息、不改公告；
- 排期的语义不做判断：公告写什么就是什么，页面不替人「修正」日期；
- 页面是只读报表——排期的事实来源是群公告，改排期得回群公告改；页面上拖不了条，也不会写回群。
