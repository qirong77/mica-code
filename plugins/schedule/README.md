# Schedule

本机的一份排期，与任何聊天工具无关：侧栏一行 `Schedule` 入口，点开是整页甘特图——**一个计划
一行**，行里的彩色条是它的阶段（开发 / 联调 / 测试 / 上线，名字随你写）。

数据就在 `$MICA_HOME/plugin-data/schedule/data.json`，两个入口改同一份：

| 入口                      | 谁在用 | 干什么                                             |
| ------------------------- | ------ | -------------------------------------------------- |
| 整页甘特图                | 人     | 新建计划、横拖建条、拖条改期、直接写名称与起止日期 |
| `schedule` 工具 + `skill` | 模型   | 用户说一句「把联调推到下周」就去改，不用用户自己拖 |

## 数据长什么样

```jsonc
{
  "version": 1,
  "updatedAtMs": 1793000000000,
  "updatedAt": "10-31 18:20", // 配置页「运行状态」读它
  "summary": "2 个计划 · 5 条阶段", // 同上
  "plans": [
    {
      "id": "p_xxx", // 全局唯一，plan_id
      "name": "钱包改版",
      "note": "双十一前上线",
      "stages": [
        // 阶段 id 也全局唯一：工具按 id 定位，界面靠它保持选中
        { "id": "s_xxx", "name": "开发", "start": "2026-11-02", "end": "2026-11-06" },
      ],
    },
  ],
}
```

日期是 `YYYY-MM-DD`、含首尾；阶段名自由，颜色由名字猜（`desktop.jsx` 的 `toneOf`）。读回来一律
过 `normalizeData`：认不出的计划 / 阶段丢掉，坏掉的一条不该让整张时间线消失。

旧形态（D-Chat 公告那版的 `groups` / `edits` / `coverage`）不再支持：`normalizeData` 只读
`plans`，旧文件读出来就是一张空排期。

## 页面怎么用

- **新建计划**：右上角「新建计划」，输入名字回车。空排期时中间也有同一个入口——这是「手动创建」
  唯一需要知道的动作，先有行才谈得上往里排东西。
- **加一条阶段**：在那一行里横拖出一段日期，松手挑名字（常用阶段点一下就走，也可以自己写）；
  不想拖就点行右侧的 `＋`，它从今天起给一周，日期在菜单里直接改。
- **改期**：拖条体整体平移，拖左右两端改起止；松手即存。选中后用 `←` `→` 挪一天，`Shift + →`
  改结束、`Alt + →` 改开始——月视角一天只有几像素，靠它精修。
- **改名称 / 精确改日期**：选中条之后底部那条编辑栏里直接改，名称回车或失焦即存。
- **删**：编辑栏里的「删除」删这一条；计划行悬停右侧的垃圾桶删整个计划（要确认一次）。
- 滚轮是缩放（锚在光标，不跳视野），Shift + 滚轮或触控板横滑是平移；日 / 周 / 月换刻度，
  「今天」把视野拉回当天。顶部阶段胶囊点一下隐藏该阶段，用来只看「开发 + 上线」两条线。
- 页面每 15 秒读一次磁盘：模型在对话里改了、另一个窗口改了，都会自己出现在时间线上。

`gantt.ts` 负责纯几何（行、泳道、日期轴、缩放锚点），页面只负责画；没有阶段的计划也占一行，
那一行就是往里拖第一条阶段的地方。

## 写盘：两条路径，一把锁

同一份数据可能被三处同时改：这个窗口、另一个窗口、对话里的模型。所以**谁都不整份盖回去**：

- **工具侧**（`store.ts`）：拿跨进程锁 → 现读 → 改一条 → 写临时文件再 rename。锁被占就等
  几十毫秒重试，六次还拿不到就回报「稍后再试」。
- **页面侧**（`writer.ts`）：排一条**操作**（改哪条、改成什么），写到一半撞上版本变化就重读最新
  数据、把这一条重放上去。别的窗口改的是别的阶段时不会互相覆盖，改的是同一条则以最后一次保存
  为准。连按方向键排进来的多条操作串行执行，后一条基于前一条的结果。
- 两者用同一个锁文件 `data.json.lock`（宿主的 `plugin-host:write-data` 也用它），页面随时在读，
  先写临时文件再 rename 保证读不到半份 JSON。

## 模型那一侧：`schedule` 工具 + skill

工具只做「按 id 改一条」，不做整份对话式覆盖：

| operation      | 参数                                  | 作用                                                                     |
| -------------- | ------------------------------------- | ------------------------------------------------------------------------ |
| `list`         |                                       | 列出全部计划与阶段（带 `plan_id`、`stage_id`、今天、每条相对今天的状态） |
| `add_plan`     | `name`、`note?`                       | 新建一个计划                                                             |
| `update_plan`  | `plan_id`、`name?`、`note?`           | 改名 / 改备注（`note: ""` 清空）                                         |
| `delete_plan`  | `plan_id`                             | 删计划连同它的阶段                                                       |
| `add_stage`    | `plan_id`、`name`、`start`、`end?`    | 加一条阶段，`end` 省略即当天                                             |
| `update_stage` | `stage_id`、`name?`、`start?`、`end?` | 改名 / 改期                                                              |
| `delete_stage` | `stage_id`                            | 删一条阶段                                                               |

日期乱写（`2 月 30 日`、结束早于开始）会被拒绝并说明原因，id 过期会说「已经不在了，重新读一次」。
工具标了 `primaryAgentOnly`：子代理临时派去查东西时不该顺手改用户的排期。

随包 skill（`skill/SKILL.md`）讲的就是上面这套：先 `list` 拿 id、日期一律 `YYYY-MM-DD`、改完用
一句话告诉用户改了什么。它随插件注册进 skills 索引，正文落盘到
`$MICA_HOME/plugin-data/schedule/skill/SKILL.md`（`/` 补全插入的就是这个路径）；用户在
`$MICA_HOME/skills` 里放同名 skill 会覆盖内置这份。

## 不是这些

- 不读 D-Chat、不依赖任何聊天工具，也不联网：排期只在本机。
- 不提供定时整理、后台任务：数据本来就是本地的，不需要「同步」这一步。
- 不改别人的公告，也不做「阶段语义推导」——名字与日期都是用户说的那样。
