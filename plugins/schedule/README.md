# Schedule

本机的一份排期，与任何聊天工具无关：顶栏右侧一枚 `Schedule` 图标，点开是整页甘特图。任务平铺在
时间轴上，**同色的任务排在同一行**，时间重叠的上下错开一条道；一条任务有名称、起止日期、颜色和
一段 Markdown 备注。

数据就在 `$MICA_HOME/plugin-data/schedule/data.json`，两个入口改同一份：

| 入口                      | 谁在用 | 干什么                                                          |
| ------------------------- | ------ | --------------------------------------------------------------- |
| 整页甘特图                | 人     | 点空白新建、拖条改期、点条编辑名称 / 颜色 / 备注，导入导出 JSON |
| `schedule` 工具 + `skill` | 模型   | 用户说一句「把联调推到下周」就去改，不用用户自己拖              |

## 数据长什么样

```jsonc
{
  "version": 1,
  "updatedAtMs": 1793000000000,
  "updatedAt": "10-31 18:20", // 配置页「运行状态」读它
  "summary": "12 个任务", // 同上
  "title": "我的排期", // 页面顶部可以改
  "scale": "day", // day / week / month，上次关掉页面时的刻度
  "tasks": [
    {
      "id": "t_xxx", // 全局唯一，工具按 id 定位
      "name": "联调",
      "start": "2026-11-02",
      "end": "2026-11-06", // 含首尾
      "color": "blue", // blue / violet / emerald / amber / rose / cyan / slate
      "note": "## 前置\n- 后端接口就绪", // Markdown
    },
  ],
}
```

读回来一律过 `normalizeData`：认不出的任务丢掉，坏掉的一条不该让整张时间线消失。颜色认不出落回
蓝色，日期只留 `YYYY-MM-DD`。

旧形态（`plans` / `stages`）不再支持：`normalizeData` 只读 `tasks`，旧文件读出来就是一张空排期。
导出的 JSON 与 `qirong-application/apps/gantt` 同形（`title` / `scale` / `tasks`），两边可以互相导入。

## 页面怎么用

- **新建**：右上角「新增任务」从今天起给 5 天；也可以在时间轴空白处点一下按那天新建、横向拖一段
  按选中区间新建。松手就打开编辑弹窗。
- **改期**：拖条体整体平移，拖左右两端改起止；松手即存。
- **编辑**：点一下任务条打开弹窗，改名称、起止、颜色和 Markdown 备注；删除要点两次。
- **刻度 / 缩放**：日 / 周 / 月换刻度，`−` `100%` `+` 调缩放（点百分比回到 100%）。滚轮直接缩放
  （锚在光标，不跳视野），Shift + 滚轮或触控板横滑是平移；「今天」把视野拉回当天。
- **备份**：右侧图标导出 JSON、导入 JSON、清空全部任务（清空要点两次）。
- **空排期**：中间一块虚线卡片，可以「新增任务」或「载入示例」。
- 页面每 15 秒读一次磁盘：模型在对话里改了、另一个窗口改了，都会自己出现在时间线上（有未保存
  的改动或弹窗开着时跳过）。

`gantt.ts` 负责纯几何（按颜色分行、泳道、日期轴、缩放锚点），页面只负责画。

## 写盘：两条路径，一把锁

同一份数据可能被三处同时改：这个窗口、另一个窗口、对话里的模型。所以**谁都不整份盖回去**：

- **工具侧**（`store.ts`）：拿跨进程锁 → 现读 → 改一条 → 写临时文件再 rename。锁被占就等
  几十毫秒重试，六次还拿不到就回报「稍后再试」。
- **页面侧**（`writer.ts`）：排一条**操作**（改哪条、改成什么），写到一半撞上版本变化就重读最新
  数据、把这一条重放上去。别的窗口改的是别的任务时不会互相覆盖，改的是同一条则以最后一次保存
  为准。拖动产生的多条操作串行执行，后一条基于前一条的结果。
- 两者用同一个锁文件 `data.json.lock`（宿主的 `plugin-host:write-data` 也用它），页面随时在读，
  先写临时文件再 rename 保证读不到半份 JSON。

## 模型那一侧：`schedule` 工具 + skill

工具只做「按 id 改一条」，不做整份对话式覆盖：

| operation     | 参数                                                    | 作用                                                               |
| ------------- | ------------------------------------------------------- | ------------------------------------------------------------------ |
| `list`        |                                                         | 列出全部任务（带 `task_id`、今天、颜色与相对今天的状态、备注摘要） |
| `add_task`    | `name`、`start`、`end?`、`color?`、`note?`              | 加一条任务，`end` 省略即当天                                       |
| `update_task` | `task_id`、`name?`、`start?`、`end?`、`color?`、`note?` | 改名 / 改期 / 换色 / 改备注（`note: ""` 清空）                     |
| `delete_task` | `task_id`                                               | 删一条任务                                                         |

日期乱写（`2 月 30 日`、结束早于开始）会被拒绝并说明原因，id 过期会说「已经不在了，重新读一次」。
工具标了 `primaryAgentOnly`：子代理临时派去查东西时不该顺手改用户的排期。

随包 skill（`skill/SKILL.md`）讲的就是上面这套：先 `list` 拿 id、日期一律 `YYYY-MM-DD`、颜色决定
行、改完用一句话告诉用户改了什么。它随插件注册进 skills 索引，正文落盘到
`$MICA_HOME/plugin-data/schedule/skill/SKILL.md`（`/` 补全插入的就是这个路径）；用户在
`$MICA_HOME/skills` 里放同名 skill 会覆盖内置这份。

## 不是这些

- 不读 D-Chat、不依赖任何聊天工具，也不联网：排期只在本机。
- 不提供定时整理、后台任务：数据本来就是本地的，不需要「同步」这一步。
- 不改别人的公告，也不做「任务语义推导」——名称与日期都是用户说的那样。
