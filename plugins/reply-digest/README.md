# Long Reply Digest（reply-digest）

在一次 Agent 回合成功结束后，读取这次会话最后一条 assistant 回复。如果回复满足以下任一条件，插件就调用摘要模型生成一段短摘要，并以独立的可收起摘要展示。摘要正文沿用对话区 Markdown 渲染，支持标题、列表、代码和表格：

- 默认字符数达到 1800；
- 默认非空行达到 36 行。

短回复不会调用模型。摘要请求开始前就展示「正在整理」摘要卡和轻量运行中动画，完成后在原位替换成摘要；失败或空结果显示未生成摘要及说明，取消、插件停用或新一轮开始会立即停止运行中状态。摘要请求在后台执行，不阻塞原回合收尾；请求绑定原会话，迟到的旧结果不会覆盖新一轮摘要，也不会错写到当前选中的另一条会话。回合中止、失败、`mica exec` 一次性执行和没有持久会话 UI 的宿主不会触发摘要。

## 设置

在 **Settings → Plugins → Long Reply Digest** 中可以调整字符数阈值、非空行阈值、摘要输入上限、摘要长度上限和提示词。摘要模型默认复用当前会话模型，也可以在插件的模型设置中单独配置。

摘要输入默认最多 12,000 字符，展示最多 600 字符。插件只保留最后一条 assistant 回复，不把工具调用、旧轮次或 notice 再发给摘要模型。摘要卡属于独立的 `digest` notice，以插件名和 input id 作为 `command`，复用 running notice 的原位替换，保留各轮摘要，不会被误画成低调的 `/compact` 状态提示。

桌面端采用方案 C：通过共享 `CollapsiblePanel` 复用真实 Arco Collapse，默认展开，点击标题或聚焦后按 Enter 可收起 / 展开。摘要保持在原回复之后，收起只影响摘要，不改动原回复或摘要生成流程；外观使用主题中性色和对话字号，不再使用渐变、ask 识别色、阴影或内外双框。正式组件与 `digest-design` / `reply-digest` 两个探针共用同一容器。
