# Session Tags

会话标签：**标签由你自己定义**（名字 + 颜色），一个会话可以挂多个。

- 标签是**跨分区的检索维度**，不是第三种归档方式：侧栏的 Pinned / Projects / Recent 仍然
  遵守「一个会话只在一个位置」，标签只挂在会话上，不改归属。
- 标签的 id 与名字、颜色解耦，所以**改名、换色不会动已经打过的标**。
- 行内圆点按标签表顺序排，不按添加顺序，所以打标之后位置不会跳。
- 首次装上会预置一个「待 review」，之后完全由你维护（删空了也不会再长出来）。

## 两个入口，各管一件事

| 入口                                                          | 干什么                               |
| ------------------------------------------------------------- | ------------------------------------ |
| 桌面端标签整页（Settings → Plugins → Session Tags →「打开标签」） | **定义标签**：新增、改名、换色、删除 |
| 会话行右键菜单 / `/tags`                                       | **给会话打标、去标**                 |

标签的维护只在页面里：新增要填名字还要挑颜色，塞进命令语法只会变成一套要记的规矩。
所以 `/tags` 只剩打标相关动词，`add` 也只认已有的标签名。

那张页面**不占侧栏一行**：清单只声明 `desktop.page`、不声明 `desktop.entry`，所以侧栏顶部
没有 `Tags`——维护标签是偶尔才做的事，打标才是每天在会话行右键里做的。

## 命令

| 命令                       | 作用                                     |
| -------------------------- | ---------------------------------------- |
| `/tags`                    | 列出所有标签、各自的用量与当前会话的标签 |
| `/tags add <标签名>`       | 给当前会话打标，可跟多个标签             |
| `/tags remove <标签名>`    | 去标                                     |
| `/tags clear`              | 清空当前会话的标签                       |

`<标签名>` 大小写不敏感，名字含空格也能写（按最长匹配吃词）。

## 页面

从配置页的插件详情点「打开标签」打开整页（整页盖在设置之上，关掉就回到那张卡）：

- 每一行是一个标签：色点、名字、挂在几个会话上；右边是「改名 / 换颜色」与「删除」。
- 底部是新增：输入名字、点一个色板圆点、按回车或点「添加」。
- 删除是两段式（先点一次进入确认态）：删标签会把它从所有会话上摘掉。
- 最多 24 个标签（与宿主的 `session-annotations.json` 上限一致），重名与空名字当场拒绝。

## 侧栏

桌面端会话行直接显示彩色圆点（最多 3 个，多出来的折成 `+N`），右键菜单里是全部标签、
已挂上的打勾的菜单项，点一下切换。

宿主这边**不认识「标签」**：它只读插件数据目录里的 `session-annotations.json`，按里面的
`options` 画点、按 `options` 的名字做菜单项。所以换一个插件写同样格式的文件（优先级、
审阅状态……）界面照样能用，宿主代码一行不用改。结构定义见
`packages/mica-plugin/sessionAnnotations.ts`。

页面改标签表走的是宿主的通用能力面 `api.annotations`
（`read()` / `writeOptions(options)`，见 `apps/desktop/src/host/session-annotations.js`）：
整份替换、跨进程锁内原子写、按通用结构归一化，并且把删掉的项同时从会话归属里摘掉；
写完广播 `annotations:changed`，所有窗口的侧栏跟着重画，不必重读整份会话列表。

## 存储

`$MICA_HOME/plugin-data/session-tags/session-annotations.json`：

```json
{
  "version": 1,
  "name": "Session Tags",
  "options": [{ "id": "tag-1", "label": "待 review", "color": "#FF9500" }],
  "assignments": { "<sessionId>": ["tag-1"] }
}
```

- `options[].id` 是稳定键（`tag-1`、`tag-2`…，由插件分配）；`label` 与 `color` 随时可改。
- 不能放 `ctx.sessionState`：那是一种会话内的状态，而标签要能跨会话列出来。
- 不能放 `ctx.settings`：插件设置只能存清单里声明过的键、值一律是字符串。
- 坏文件保留原样并上报一次健康状态，命令准确返回读写失败，修复后可直接重试。
- 会话被删掉之后它的 `assignments` 会变成孤儿：渲染时按会话列表 join，孤儿看不见。
- 插件初始化与修改命令在进程锁内读改写；其他插件宿主正在更新时明确提示重试。

### 旧形态不再支持

v1 是 macOS Finder 那种**7 个固定色槽**（red / orange / yellow / green / blue / purple / gray，
只能改名、不能新增）。v2 起标签自由定义，启动时一次性收敛：

- 没改过名、也没挂过任何会话的旧色槽直接清掉（那只是默认值，不是用户的数据）；
- 改过名字、或挂着会话的旧色槽保留成普通标签，id 仍是 `red` / `blue` 这些，归属不动。
- 清完一个都不剩（从没用过这个插件）就给一个「待 review」，和全新装好时一样。

不写迁移脚本，也不保留运行时兼容分支：收敛就地发生在读完文件的那一刻。

## 文件

| 文件             | 职责                                                   |
| ---------------- | ------------------------------------------------------ |
| `model.ts`       | 纯数据层：标签表、色板、增删改校验、归属与各种收敛规则 |
| `store.ts`       | 那份 `session-annotations.json` 的定位、读取与原子写   |
| `index.ts`       | 注册 `/tags` 命令，首次运行落盘                        |
| `desktop.jsx`    | 桌面端 Tags 整页（标签的增删改都只在这里）             |
| `*.test.ts`      | 纯数据层、命令、页面交互的行为测试                     |

`model.ts` **不能 import 任何 node 内置模块**：桌面端页面直接 import 它做校验，撞上
`node:fs` 会让页面构建失败。
