# Session Tags

会话标签，形态照 macOS Finder 的彩色圆点：**7 个固定色槽**（red / orange / yellow / green /
blue / purple / gray），每个色槽有一个可改的名字，一个会话可以挂多个。

- 标签是**跨分区的检索维度**，不是第三种归档方式：侧栏的 Pinned / Projects / Recent 仍然
  遵守「一个会话只在一个位置」，标签只挂在会话上，不改归属。
- 颜色固定，不能新增色槽——自由取色在深色侧栏上对比度不可控，要表达新分类就改某个色槽的名字。
- 行内圆点按固定色序排列，不按添加顺序，所以打标之后位置不会跳。

## 给用户用的，不是给模型用的

这个插件**不注册 tool，也不往 system prompt 里塞任何东西**。标签是用户自己的分类习惯：
模型既不了解用户为什么这么分，也不该替他整理，更不该因为看见标签而改变对任务的理解。
打标只有两个入口，都在用户手上——桌面端会话行右键菜单，以及 CLI / TUI 的 `/tags` 命令。

## 命令

| 命令                         | 作用                                      |
| ---------------------------- | ----------------------------------------- |
| `/tags`                      | 列出 7 个色槽、各自的用量与当前会话的标签 |
| `/tags add <颜色>`           | 给当前会话打标，可跟多个颜色              |
| `/tags remove <颜色>`        | 去标                                      |
| `/tags rename <颜色> <名字>` | 改色槽名字（改完全局生效）                |
| `/tags clear`                | 清空当前会话的标签                        |

`<颜色>` 接受色槽 id（`red`）、默认名（`Red`）或用户改过的名字，大小写不敏感。

## 侧栏

桌面端会话行直接显示彩色圆点（最多 3 个，多出来的折成 `+N`），右键菜单里是 7 个带色点、
已挂上的打勾的菜单项，点一下切换。

宿主这边**不认识「标签」**：它只读插件数据目录里的 `session-annotations.json`，按里面的
`options` 画点、按 `options` 的名字做菜单项。所以换一个插件写同样格式的文件（优先级、
审阅状态……）界面照样能用，宿主代码一行不用改。结构定义见
`packages/mica-plugin/sessionAnnotations.ts`。

## 存储

`$MICA_HOME/plugin-data/session-tags/session-annotations.json`：

```json
{
  "version": 1,
  "name": "Session Tags",
  "options": [{ "id": "red", "label": "Red", "color": "#FF3B30" }],
  "assignments": { "<sessionId>": ["red", "blue"] }
}
```

- 不能放 `ctx.sessionState`：那是一种会话内的状态，而标签要能跨会话列出来。
- 不能放 `ctx.settings`：插件设置只能存清单里声明过的键、值一律是字符串。
- 文件里缺了某个色槽会被自动补回来，同时保留会话标签归属（7 个槽是产品契约）；坏文件保留原样并上报一次健康状态，命令准确返回读写失败，修复后可直接重试。
- 会话被删掉之后它的 `assignments` 会变成孤儿：渲染时按会话列表 join，孤儿看不见。
- 插件初始化和修改命令在进程锁内读改写；其他插件宿主正在更新时明确提示重试。自定义名字包含空格时，解析只搜索现有标签名字的最大词数，长参数不会枚举所有后缀。
