# Subagent

派一个独立的 mica 会话去干活，并观测它。子会话是一个常驻的 `mica app-server` 进程：
自己的上下文、自己的会话文件，父会话通过结构化事件（正文、工具调用、
轮次终态、用量）看它，而不是读屏。

`plugins/subagent-legacy` 是**旧的那一半**：进程内委派，子代理活在父进程里、共享父会话的
模型与工具，跑完把结果带回来。两者可以同时启用——要干净环境、要盯着跑很久、要事后接着追问，
用本插件；要把一段推理拆开并行，用 legacy 的 `agent` 工具。

## 四个动词，一个主语

主语是**一条被驱动的 mica 会话**（`session_id`，可只给唯一前缀），动词按意图分。同一件事的
不同力度用参数表达，不按实现分层摊成一排工具名——工具 schema 进每次请求的前缀，名字越少越省。

| 工具               | 做什么                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------ |
| `subagent_drive`   | 给它活：只给 `prompt` 就新建；给 `session_id` 就接管或追加一句（跑着排到下一迭代边界，空闲开新一轮）。         |
| `subagent_inspect` | 看它（只读）：状态（一条 / 全部一行 / `full: true` 收尾）与内容三档 `view: turns → grep → transcript`；`session_ids` 可一次读多条。 |
| `subagent_wait`    | 等它：`idle` / `text` / `turn`，可多个（`any`）。                                                            |
| `subagent_stop`    | 停它：`interrupt` 打断这一轮（等到真的停下才回报）/ `close` 收进程；`all` 选全集、`idle` 只收跑完的，给了 id 就只在那几条里挑。 |

并发、迭代轮数、token 与嵌套层数都不设上限（每个子会话都是完整进程，资源开销自己判断）。

派发的第一句话会自动变成一个 issue 信封，带上父会话标题 / ID 与 `<task>` 内容；B 再派 C
时会重新生成 B → C 的上下文。接管与追加也走同一个 `drive`：传 `session_id` 就认**会话 ID**
（不限于本进程派生的），之后 inspect / wait / stop 与派生出来的那条完全一样用——同一个会话
只有一种操作方式，没有「派生一套工具 + 通用控制另一套工具」。

**读结果按成本分层**：`subagent_inspect` 的状态一行到一屏 → `view: "turns"`（每轮一行）
→ `view: "grep"`（命中行，`scope: "tools"` 连命令输出一起搜）→ `view: "transcript"`（正文，
按字符预算截断）。一次读多条用 `session_ids`（预算按条分摊）；`full: true` 与 `view` 同用时
再附一份收尾投影。收尾用 `subagent_inspect({ full: true })`：一次给出每个子会话的状态、
最后一轮结论、失败的工具、用量，再 `subagent_stop({ action: "close", idle: true })` 收掉跑完的。

**它自己会说话**：轮次结束、进程退出、停滞都记成一条动态。这些动态在父
会话下一轮开工时由 prompt 段落注入一次（没有动态时整段为空，prompt 前缀不变），同时按需
在当前会话留一条 notice。`subagent_wait` 超时不会白等：条件被登记成后台提醒，成立时同样
跟着下一轮到达。

## 生命周期

- **跟着父会话走**：父会话结束、宿主退出，子进程一起收掉（`onDispose` 等待真正退出）。
- **空闲回收**：默认不回收（像正常会话一样在）；在插件设置里填分钟数才收，且只在结果已被
  读过之后才收，会话历史保留。
- **卡住判定**：在跑但默认 5 分钟没有新输出，记一条「可能卡住」，并给出当前工具的已跑时长。
- **接回来**：`subagent_drive({ session_id })` 用 `thread/resume` 接管已有会话。resume 不发
  通知，所以历史从 `$MICA_HOME/sessions/<id>.json` 补进投影（工具调用只有名字）。

两项阈值在插件设置里（停滞分钟、会话内提醒开关），改完立刻生效，不需要重启。插件里没有
任何会自动中止子会话的机制：停滞只发一条提醒，回收默认关闭（0 = 不回收）。

## 界面

桌面端声明 `desktop.panel`（宿主没有桌面能力面时自动缺席，工具照常可用）：右侧抽屉列出每个
子会话的状态、最近动静、用量，行内可「看详情 / 打断 / 收掉」；有子会话在跑时输入框上方常驻
一条「N 个在跑」。按钮只做一次点击能完成的事（打断、收掉、看详情），需要模型参与的（汇总结果、
派一个去干活、让它接着干）只把提示词放进输入框，不替用户发送。

## 边界

- 子会话看不到父会话的对话：目标、约束、路径、验收方式都要写进 `prompt`。
- `subagent_drive` 接管不到当前会话自己；目标在其它进程运行时服从 turn lease，返回 busy 而不是并发写入。
- 多个子会话同时改同一个仓库等于没人在管：写代码的活一次只派一个，`cwd` 写到具体目录。
- 角色默认继承父会话当前的角色；模型、档位可覆盖。迭代与 token 不设参数，也不设上限。
- 子会话的落盘标题就是 `subagent_drive` 传的 `title`（缺省取任务第一行）：派活时顺手改名，
  侧栏才不会显示成 `<context>` 那一行。
- 会话级 MCP 配置随委派继承，子进程是纯 headless 宿主，不继承桌面插件宿主能力。

架构与实现细节见 `registry.ts`（登记表、事件、看门狗）、`subagentProcess.ts`（进程与协议）、
`transcript.ts`（通知流投影）、`views.ts`（四种成本不同的文本视图）、`history.ts`（接管时的历史）、
`panel.ts`（桌面面板）。
