# Sidecar

派一个独立的 mica 会话去干活，并观测它。子会话是一个常驻的 `mica app-server` 进程：
自己的上下文、自己的会话文件、自己的并发名额，父会话通过结构化事件（正文、工具调用、
轮次终态、用量）看它，而不是读屏。

## 三块能力

**派活与驱动**：`sidecar_spawn` 开一个并投第一句话，`sidecar_send` 追加一句（跑着时排到
下一迭代边界，空闲时开新一轮），`sidecar_abort` 打断当前这一轮，`sidecar_close` 收进程。
最多同时 4 个在跑；深度上限 2 层（每层都是完整进程，再深就是指数级进程树）。

**读结果，按成本分层**：`sidecar_status`（一行到一屏的进度）→ `sidecar_turns`（每轮一行）
→ `sidecar_grep`（命中行，`scope: "tools"` 连命令输出一起搜）→ `sidecar_transcript`（正文，
按字符预算截断）。收尾用 `sidecar_collect`：一次给出每个子会话的状态、最后一轮结论、失败
的工具、用量，`close: true` 顺手收掉已经跑完的。

**它自己会说话**：轮次结束、进程退出、停滞、超出 token 预算都记成一条动态。这些动态在父
会话下一轮开工时由 prompt 段落注入一次（没有动态时整段为空，prompt 前缀不变），同时按需
在当前会话留一条 notice。`sidecar_wait` 超时不会白等：条件被登记成后台提醒，成立时同样
跟着下一轮到达。

## 生命周期

- **跟着父会话走**：父会话结束、宿主退出，子进程一起收掉（`onDispose` 等待真正退出）。
- **空闲回收**：跑完、结果已被读过、空闲超过阈值（默认 15 分钟）就收进程，会话历史保留。
- **卡住判定**：在跑但默认 5 分钟没有新输出，记一条「可能卡住」，并给出当前工具的已跑时长。
- **接回来**：`sidecar_attach({ session_id })` 用 `thread/resume` 接管已有会话。resume 不发
  通知，所以历史从 `$MICA_HOME/sessions/<id>.json` 补进投影（工具调用只有名字）。

几项阈值与默认预算在插件设置里（停滞分钟、空闲回收分钟、默认 token 预算、会话内提醒开关），
改完立刻生效，不需要重启。

## 界面

桌面端声明 `desktop.panel`（宿主没有桌面能力面时自动缺席，工具照常可用）：右侧抽屉列出每个
子会话的状态、最近动静、用量，行内可「看详情 / 打断 / 收掉」；有子会话在跑时输入框上方常驻
一条「N 个在跑」。按钮只做一次点击能完成的事（打断、收掉、看详情），需要模型参与的（汇总结果、
派一个去干活、让它接着干）只把提示词放进输入框，不替用户发送。

## 边界

- 子会话看不到父会话的对话：目标、约束、路径、验收方式都要写进 `prompt`。
- 多个子会话同时改同一个仓库等于没人在管：写代码的活一次只派一个，`cwd` 写到具体目录。
- 角色默认继承父会话当前的角色；模型、档位、`max_turns`、`max_tokens` 可覆盖。
- 会话级 MCP 配置随委派继承，子进程是纯 headless 宿主，不继承桌面插件宿主能力。

架构与实现细节见 `registry.ts`（登记表、事件、看门狗）、`sidecarProcess.ts`（进程与协议）、
`transcript.ts`（通知流投影）、`views.ts`（四种成本不同的文本视图）、`history.ts`（接管时的历史）、
`panel.ts`（桌面面板）。
