# 连接（Connections）

连到另一台机器上的 Mica 运行时：打开那个地址之后，文件、终端、会话都来自那台机器。
「连接过哪些运行时」是这份清单的全部内容——连过的地址排在最前，可以起一个备注
（`办公室的 Mac`），也可以直接输入一个没连过的地址。

- 一台运行时在界面上就是一个 origin，所以切换 ＝ 打开那个地址：桌面端由外壳弹新窗口，
  浏览器里开新标签页。
- 地址规范化、回环判断、同机比较都复用 `mica-web-shared/runtime-address`，不在插件里再写
  一份规则。
- 清单里的地址**不代表它现在活着**：探活是打开时的一次请求，失败就是一句可读的错误。

## 反过来：让别的机器连这台机器

卡片底部的「局域网/公网可访问」是反方向的那一半。默认这台机器的运行时只把**分享视图**
开放给非本机请求，`/`、`/files`、`/terminal*`、`/remote/*`、`/mcp/*` 一律 404——别人拿到
一个地址也进不来。

打开开关之后，非本机请求访问完整界面时先落到登录页（`/__access`），输对访问口令才放行；
口令默认 `0000`，可以在同一个输入框里改。分享链接（`/share?session=…`）不受影响，仍然是
打开就能看的那一条会话——**链接本身就是那张凭据**：只有指向真实存在会话的链接才换得到
分享页要用的那张 cookie，裸 `/share` 或编造 id 换不到。

策略归运行时所有（`$MICA_HOME/remote-access.json`），因为「谁能看哪个路径」只在
`apps/desktop/src/server/index.js` 的请求分派里决定；卡片通过宿主的 `api.access`
（`plugin-host:access-get|set`）读写它，不自己拼路径、也不写第二份判定。

`/api/*` 一律要凭据（口令，或打开过有效分享链接得到的那张 cookie），开关开不开都一样：
它等于整台机器（真 shell、任意读写、配置里的 API key），不该是「知道地址就能用」的东西。
所以分享链接照旧工作，而裸 `curl` 直接打接口不再等于拿到整台机器。

唯一例外是探活指纹 `GET /api/health`（只回 `{ ok, app, access }`，没有会话也没有数据）。
没有它，上面那条「连到别的机器」永远走不通：卡片是先探活再开窗的，探活被口令挡掉就只剩
一句「连接失败」。`access` 让卡片能区分两种情况——对方没开这个开关时直接说清该去哪台机器上
做什么，而不是替用户打开一个 404 窗口。

## 跨网络：连中转机链接

两台机器不在同一网络时也能用——地址栏里粘一条 **mobile-relay 链接**：

```
https://mica.qirong77.com/?t=<那台机器的口令>&session=<会话 id>
```

它和直连地址是两种东西：链接指向的不是「这个 origin 上的运行时」，而是「中转机转给某台
机器的界面」，凭据就在查询串里。所以：

- 探活走 `/api/health?t=…`，认中转机回的 `label`（那台机器的名字）；口令过时它说清是口令
  的问题，而不是「不是 Mica 运行时」。
- 打开的是**完整链接**（`t` 与 `session` 都留着）——把查询串抹掉就等于把凭据抹掉。
- 清单按「中转机 + 令牌」去重：同一台机器换一条会话仍是同一条记录，入口跟着更新。
- 行里显示时 `t=` 打码成 `t=…`：它是凭据，不该明文摊在侧栏上。
- 桥没连上时探活仍算通（`online: false`），先打开并说明「页面会自己重试」。
- 裸中转机域名没有机器身份，不会把它背后的所有连接都当成「当前」并隐藏；清单仍可切换到各台机器。

粘裸域名（不带 `?t=`）时探活会认出这是一台中转机并让你补全链接，而不是报网络错误。
这条链接和手机用的是同一条，手机上复制过来即可。

## 数据

`$MICA_HOME/plugin-data/connections/data.json`：

```json
{ "version": 1, "peers": [{ "url": "http://10.0.0.2:9102", "note": "办公室的 Mac" }] }
```

文件由插件前端经宿主的 `plugin-host:read-data|write-data` 读写，宿主不解析结构——连接清单
是插件自己的事。旧版本存的是纯地址数组，读取时一并收敛成 `{ url, note }`（见 `peers.ts`）。
同一卡片按顺序完成读写，跨窗口通过宿主的内容版本比较写入；冲突时重读最新清单并重放本次修改，最多重试八次。保存失败会显示原因，不把未落盘的修改显示成成功。备注保存失败时保留输入供重试；探活和访问策略保存会同步阻止重复触发，保存返回时保留期间继续编辑的口令草稿。

## 为什么后端是空的

这个插件的能力全在桌面端的卡片里（`desktop.jsx`）：探活、读写清单、打开地址都需要
运行时地址与外壳能力。`index.ts` 因此不注册 tool、不注册命令、不往 system prompt 里加
任何东西——连哪台机器是用户的决定，模型不需要知道。

## 入口范围

侧栏入口来自清单的 `desktop.entry`，只有**随包插件**（官方插件目录）才会出现在侧栏：
用户插件挂在 `$MICA_HOME/plugins` 下，宿主不读它们的 `desktop.jsx`。

## 文件

| 文件            | 职责                                       |
| --------------- | ------------------------------------------ |
| `plugin.json`   | 清单：id、图标、桌面入口                   |
| `index.ts`      | 空的 setup，只留一条启动日志               |
| `peers.ts`      | 纯数据层：清单的收敛、去重、备注与过滤     |
| `peers.test.ts` | 纯数据层的行为测试                         |
| `desktop.jsx`   | 侧栏卡片：当前运行时、其他运行时、输入地址、远程访问口令 |
