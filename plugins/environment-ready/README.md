# Environment Ready

为当前任务明确登记的本机服务提供一张环境摘要卡。模型用 `environment_ready` 管理最多 6 个目标；桌面面板提供逐目标的打开、检查、移除操作。插件不从命令、日志或其它工具结果中自动发现服务，也不启动、停止或重启任何进程。

## 使用

仅当当前任务确需持续探测已知本机服务时登记，不要为了生成卡片而登记；一次性检查使用合适的一次性探测方式。`set` 替换本次任务的完整目标清单，登记本身不立即联网。目标必须包含稳定的 `id`、名称 `label` 和 `kind`。

```json
{
  "operation": "set",
  "targets": [
    { "id": "web", "label": "Web", "kind": "http", "url": "http://localhost:3000/health" },
    { "id": "db", "label": "Database", "kind": "tcp", "host": "127.0.0.1", "port": 5432 }
  ]
}
```

| operation | 参数           | 行为                                              |
| --------- | -------------- | ------------------------------------------------- |
| `list`    | 无             | 读取清单、检查时间与结果，不联网                  |
| `set`     | `targets` 数组 | 原子替换完整清单，最多 6 项；实际变化时清空旧结果与收起状态，相同清单保持原状 |
| `remove`  | `id`           | 移除一个目标，使进行中的旧检查失效                |
| `check`   | 可选 `id`      | 检查全部或一个目标                                |
| `clear`   | 无             | 清空清单并取消旧检查                              |

任务切换后模型应移除不再需要的目标，或按需替换、清空清单；新任务仍需持续检查的目标应保留。该工具通过 `MicaTool` 注册且标记 `primaryAgentOnly`，子代理不能改动主会话的环境清单。

## 检查边界

首版**只支持回环地址**：`localhost`、`127.0.0.0/8`、`::1`。`localhost` 固定转换为 `127.0.0.1`，不进行 DNS 发现。远程域名、局域网地址、通配监听地址（`0.0.0.0` / `::`）、IPv4 映射 IPv6 均拒绝，不提供远程扫描开关。HTTP URL 只允许 `http` / `https`，不得包含用户凭证。

- HTTP 每次发送一个 GET，最多等待 5 秒，使用 `AbortController` 取消；不发送 cookies、认证头或 referrer，不读取响应正文。`redirect: manual` 保留确切 3xx 状态码并且不跟随重定向，包含指向远程地址的重定向。
- `reachable: true` 表示收到了 HTTP 响应，包括 3xx、4xx、5xx。`healthy: true` **仅表示 HTTP 2xx**；这不是业务健康检查。3xx 和其它非 2xx 显示可达、非 2xx。
- TCP 只尝试已登记地址与端口的一次连接。socket 设置 5 秒超时，连接成功、错误、超时或取消后销毁；TCP 的 `healthy` 一直为 `null`，不推断应用健康。
- 连接失败、超时与其它探测异常写成逐目标状态，保留 `checkedAt`，不让一行失败吞掉整个检查结果；错误正文不落入状态或埋点。

## 卡片、面板与时效

只有登记服务后才出现一张聚合卡片，最多 3 个按钮：检查、详情、收起。详情首屏逐项显示地址、当前结果与检查时间（尚未检查时明确标示），并通过共享弹窗的「管理服务」进入详细面板。面板的 HTTP 行提供打开、检查、移除，TCP 行只提供检查、移除。打开 HTTP 目标由宿主交给系统浏览器执行，探测器本身不会打开页面。

卡片的「收起」按配置 revision 写入会话状态，轮询、再次检查和重复 set 相同清单不会把它重新弹出；实际更新清单、从插件入口重新打开环境详情，或在详细面板点击「重新显示摘要」后恢复。入口使用清单的 `desktop.panel.open: reopen` 动作，使重新打开能显式清除收起记录，普通视图轮询保持只读。

所有结果带检查时间。只有本插件当前实例亲自检查过、且不超过 60 秒的结果能显示为当前可达或检查通过。重开插件、恢复会话、未来时间戳或超过 60 秒的结果显示为未知 / 历史待检查；工具返回的 `lastStatusCode` 明确是上次状态码，过期时 `reachable` 和 `healthy` 为 `null`。

目标、结果和收起记录位于本会话的 `pluginState['environment-ready']`（`version: 1`），随宿主 checkpoint 保存；插件不另建全局服务清单。后台探测只更新运行中的状态，不额外触发会话保存，因此关闭前最后一次探测不保证落盘；恢复后始终重新检查。恢复时重新归一化目标和状态，非法或远程目标丢弃，`healthy` 从确切 HTTP 状态码重新推导。每次异步检查捕获 owner，读写同一 owner；返回结果前再次核对会话身份，配置快照或 revision 变化后旧结果不回写。任意时刻只运行一轮检查，重复触发返回 busy。插件卸载会取消在途 HTTP 请求和 TCP socket，并阻止结果回写。

## 设置与调度

| 设置              | 默认值   | 含义                                                                           |
| ----------------- | -------- | ------------------------------------------------------------------------------ |
| `intervalSeconds` | `"30"`   | 由 `ctx.background` 调度，限制在 10–300 秒；只检查已登记目标，setup 不立即检查 |
| `telemetry`       | `"true"` | 允许统一的本地使用元数据埋点；关闭立即生效                                     |

设置值遵循插件系统的字符串约定。间隔超过 60 秒时，结果在下次检查前可自然进入未知状态。插件使用宿主后台能力，无自行维护的 interval、系统服务或独立常驻进程。

## 使用情况记录

复用 `packages/mica-plugin/PluginExperience.ts` 的 `createPluginExperience(ctx)`。只记录 impression、click、dismiss、update、failure、check、clear 及固定 action、surface、结果枚举、revision、数量和耗时；会话归属交给共享 helper 处理。目标 URL、主机、端口、名称、路径、命令、日志和异常正文都不作为埋点字段。

卡片的 `impressionAction` 使用宿主的展示回调，不在轮询 `view()` 中伪造曝光。卡片 revision 和操作 key 绑定清单快照；逐目标的打开、检查、移除均验证 revision key，旧界面不能操作同 id 的新目标。

## 实现与验证

- `state.ts`：目标校验、持久状态归一化、时效和间隔边界。
- `probes.ts`：可注入 fetch/socket 的有限时探测。
- `controller.ts`：owner、revision、取消、去重、状态与埋点。
- `Tool.ts`、`panel.ts`、`index.ts`：工具、共享卡片 / 面板和宿主装配。
- `*.test.ts`：注入依赖验证网络选项、重定向、超时、TCP 释放、卸载取消、归属隔离、旧结果竞态、持久数据归一化、卡片操作键和遥测关闭；不启动真实服务。

官方清单与入口登记在 `packages/mica-official-plugins`。依赖桌面能力，TUI 与一次性 CLI 宿主跳过整个插件。卡片通过 `dynamicShortcuts` 获取动态视图，沿用统一主题与面板组件。
