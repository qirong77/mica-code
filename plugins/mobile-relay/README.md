# Mobile Relay

手机经一台公网中转机打开这台机器上的 Mica：看到的是真实的桌面端界面（同一份会话、同样的流式输出），
不是另做的一套精简页。

## 形态

```
手机 ──HTTPS/SSE──> 中转机 ──短轮询──> 这台机器 ──回环──> Mica 运行时
```

- **中转机**（`relay/relay.mjs`）托管 `apps/desktop/out/renderer` 的构建产物，并把 `/api/invoke`、
  `/api/events`、`/api/env`、`/api/image` 实现成与桌面运行时相同的形状，所以页面一行不用改。
- **这台机器**（`agent/bridge.mjs`）只做出站短轮询：没有监听端口、没有常驻连接、不转发端口，
  只按白名单把语义 channel 转给 `127.0.0.1:8787`。
- 桥进程由插件通过 `ctx.background` 监管：**停用插件就杀掉它**，不会出现「插件关了还在外联」。

## 安全与「别太显眼」

| 措施 | 说明 |
| --- | --- |
| TLS | nginx 终结 TLS，Let's Encrypt 证书（`sslip.io` 免费域名即可），浏览器绿锁 |
| 应用层加密 | 轮询体 AES-256-GCM，密钥由 token 经 HKDF-SHA256 派生；中转机看不到明文 |
| 按需推送 | 没有手机在看时不攒事件；静止时每轮上行 39 字节（结果未变的只回 hash） |
| 白名单 | 只放行语义 channel；终端、文件写入、`git:stage`、`config-web:invoke` 一律拒绝 |

## 安装

**交给 agent 做。** 插件带一个内置 skill（`mobile-relay-setup`），在会话里说「帮我配一下手机
访问」，它会取仓库、必要时构建页面产物、部署中转机、把你的地址与口令写回设置并验证。

自己做的场合，先在有公网 IP 的 Linux 机器上装好 `node`（≥ 18）与 `nginx`，然后在本仓库根目录：

```bash
cd apps/desktop && npm install && npx electron-vite build && cd ../..   # 只在需要现场构建时
node plugins/mobile-relay/setup.mjs --host root@<公网IP>
```

一条命令做完：生成口令 → 打包上传（`relay.mjs` + renderer 产物）→ 写 systemd 单元 →
写 nginx 站点 → 用 `sslip.io` 自动域名申请 Let's Encrypt 证书 → 起服务 →
把地址和口令**写进本机的插件设置**。

```bash
# 用自己的域名（要先把它的 A 记录指到中转机）
node plugins/mobile-relay/setup.mjs --host root@1.2.3.4 --domain mica.example.com
# 服务器 SSH 不在 22
node plugins/mobile-relay/setup.mjs --host root@1.2.3.4 --ssh-port 2222
```

### 在插件里点按钮完成（推荐）

两个入口，都开在同一块面板上：**设置 → 插件 → Mobile Relay** 的「手机访问」按钮，或者
**会话设置 → 插件 → Mobile Relay** 里的「打开面板」。面板里的内容：

- **状态**：中转地址、本机桥、手机链接
- **接中转机**：填「中转机 SSH」「SSH 端口」「这台机器的名字」，点「接入 / 部署」
- **首次部署**：面板会检查页面产物目录；找不到就给出「让 agent 构建并部署」，由会话里的一轮
  去取仓库、构建、部署

执行细节：`setup.mjs` 与 relay 三件套随包内嵌（`deploySource.ts`），运行时落到
`$MICA_HOME/plugin-data/mobile-relay/bundle/` 再交给 node 跑；进度写进 `deploy.json`，
面板的「过程」一节实时显示最近几行。

### 第二台以后的电脑接入（命令行）

中转机装好后，**另一台电脑跑同一条命令就行**，不需要额外参数：

```bash
node plugins/mobile-relay/setup.mjs --host root@<同一台中转机> --ssh-port 2222
```

它会先探测 `systemctl is-active mobile-relay`：已经部署过就只做「登记这台机器」——
往 `agents.json` 追加一条（口令按 `--label` 认领，同名机器重跑不会留重复记录），
**不重传页面、不重配 nginx、不重签证书**，全程约 20 秒，且不重启服务：
relay 每 5 秒比对 `agents.json` 的 mtime 热加载清单，已经连着的手机不会被打断。

要强制完整部署（比如升级 relay 本身）用 `--redeploy`。

每台机器各自一个口令，手机用各自的链接打开各自的页面；**一台机器的手机看不到另一台的
任何内容**（状态、事件流、结果缓存全部按口令隔离）。

有域名就传 `--domain`，没有就用自动域名。`--no-cert` 跳过证书（仅限内网调试）。
装完手机直接开打印出来的链接，不需要手动填设置。

域名走 Cloudflare 代理时要把记录设成 **DNS only**（灰云）：橙云会用自己的证书终结 TLS，
让 certbot 签不出源站证书，事件流也要多绕一层。同一台机器换域名重跑会按 `--label`
（默认取主机名）认领回原口令，不会在中转机上留下重复记录。

renderer 只从**仓库的构建产物**取（`apps/desktop/out/renderer`），或用 `--renderer` 指向
另一台机器上已构建好的那份。刻意不去读已安装应用里的产物：打包后在 `app.asar` 内，
只有 Electron 读得到，硬抠出来属于 hack 且会随版本漂移。

排查问题：`mobile_relay action=doctor`（在会话里让模型跑），逐项检查设置、桥进程、
TLS、口令、本机运行时。

## 日常怎么用

1. **这台机器**：桌面端开着就行，不用管窗口。桥由插件监管，开机自启、崩溃重拉；
   关掉「启用桥」或停用插件，进程立刻被杀掉，不会留下还在外联的东西。
2. **手机**：打开面板「状态」一节里的手机链接（`https://<中转机>/?t=<口令>`），
   建议加到主屏。看到的就是桌面端同一套界面、同一份会话。
3. **看状态**：设置 → 插件 → Mobile Relay 点「手机访问」打开面板，里面是桥在不在跑、
   中转机通不通、手机是不是正在看，以及上次部署的最近几行输出。
4. **换机器 / 重装中转机**：面板里改「中转机 SSH」再点一次「接入 / 部署」即可；
   接的是同一台中转机就只登记这台机器，指向新机器则走完整部署。

侧栏没有 `Mobile` 入口，输入框上方也不占按钮：入口只有插件自己的详情页（整页设置）和
会话设置里那一条，面板本身开在对话右侧。

**口令不能手填。** 中转机只认它 `agents.json` 里登记过的值，自己编一个（比如两位的
`dd`）永远是 401、页面显示「中转机不可达」。正确做法是点面板里的「接入这台机器」，
由 `setup.mjs` 在中转机上登记并把这个值写回插件设置；设置页的口令项现在也会直接报
「口令至少 16 位，而且要是在中转机上登记过的那个」。

手机端不提供终端与文件编辑，这两项在白名单里就是拒的。

桥脚本首次由插件落盘到 `$MICA_HOME/plugin-data/mobile-relay/bridge.mjs`，需要系统里有 `node`
（或用 `MICA_BRIDGE_NODE` 指定）。

桥按中转机下发的间隔常驻轮询（无人在看 15 秒、有人看 1 秒、有命令或流式事件 300 毫秒），
没有时段限制，也没有额外抖动。

## 设置项

| 键 | 说明 |
| --- | --- |
| `enabled` | 总开关；关掉会立刻杀掉桥进程 |
| `relayUrl` | 中转机地址，如 `https://xxx.sslip.io` |
| `token` | 访问口令，同时用于派生加密密钥 |

## 已知边界

- 需要桌面端在运行（桥轮询的是本机 `127.0.0.1:8787`）。
- **桥的存活等于「桌面端里有一个打开的会话」**：插件载在每个会话的 app-server 里，
  关掉最后一个会话页签，宿主退出，桥也随之停。插件每 3 秒检查一次并拉起，
  所以重新打开会话后 1–3 秒内恢复；手机页面 meanwhile 每 5 秒自动重试。
  要让桥彻底脱离会话，需要插件之外的常驻方式（launchd/系统服务），当前没做。
- 用户插件（`$MICA_HOME/plugins`）的卡片在手机上渲染不出：页面是构建期打的包。
- 手机端不提供终端与文件编辑。

## 改桥脚本

`agent/bridge.mjs` 是唯一源码；改完跑 `bun scripts/generate-mobile-relay-sources.mjs`
重新生成 `bridgeSource.ts`（随包运行的是内嵌那份）。

## 为什么部署不在插件里

插件只做一件事：**本机这座桥**（进程监管、设置、状态、`mobile_relay` 工具、内置 skill）。

中转机的部署放在 skill 里、由 agent 现场执行，原因有三条：

1. 中转机需要的是「这台机器上跑的那个页面」，而它只能从仓库构建——把构建产物塞进插件
   等于把一份会过期的副本编进二进制。
2. 部署要装包、申请证书、改 nginx，失败模式又杂又长，写在 skill 里能给出可读的原因；
   塞进插件只能抛一句错误。
3. 版本解耦：relay 改一行只要重新部署，不必发一个插件版本。
