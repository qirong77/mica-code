# Mica 远程访问性能复核

## 对照实测

同一台 Mac、修改前后两份隔离的 production renderer/runtime、合成会话与笔记，不读真实用户资料。Headless Chrome 的 CDP 限速为请求到响应头最少 180 ms、上下行各 2 Mbit/s。下表不是公网实测，也不含模型调用耗时。

| 场景与测量终点 | 优化前 | 优化后 | 关键变化 |
| --- | ---: | ---: | --- |
| 已读、未改笔记：点击到同一 iframe 确认正文就绪（各 10 次，中位数） | 338.8 ms | 230.0 ms | 仍是 1 个请求；整篇重读变为版本校验，接收 28,442 B → 334 B（CDP，含响应头） |
| 未挂载的已完成会话：侧栏点击到首条记录可见（各 1 次） | 640.2 ms | 345.1 ms | 恢复请求 3 个、2 轮 → 1 个、1 轮；接收 22,082 B → 21,579 B |
| 统计冷开：点击到首个 `stats:read` 完成且 KPI 可见（各 3 次，中位数） | 2,005.9 ms | 1,278.1 ms | 请求开始从约 1.79 s 提前到 1.06 s。不是全部图表就绪的耗时 |
| 独立文件编辑器冷开：`?editor=…` 到 Monaco 显示首行（各 3 次，中位数） | 7,996.4 ms | 7,809.1 ms | `files:read` 和 Monaco 下载由串行改并行，省约 190 ms |
| 首页冷开：导航到 Stats 入口可点击（各 3 次，中位数） | 3,222.6 ms | 3,266.4 ms | 未测出整页提速；首次 `ui-state:get` 回包约 3.08 s → 0.60 s，不再拖在应用资源之后 |

笔记测试走真实 Notebook 页、RPC 与沙箱消息桥，iframe 用确定性本地夹具，不代表 Lexical 或第三方 CDN 的冷启动。在另一组 API 检查里，同一份较大的合成笔记首次 gzip 正文 176,587 B，重读未改时 116 B（仅响应体）；不同版本、缺失文件、坏 JSON 和写入冲突仍各走原逻辑。真实 Monaco 文件编辑器不使用这份 iframe 夹具。

统计入口 chunk 的压缩传输由约 200 KB 降到 12 KB，另约 188 KB 的图表模块与数据同时加载；总资源没有相应缩小。Monaco 压缩仍约 920 KB，在 2 Mbit/s 下单下载就接近 4 秒。浏览器冷启动先清 HTTP 缓存；笔记切换保留缓存与已启动的 iframe。复测时从 CDP 记录 `files:read`、`monaco-runtime-*`、`stats:read`、`StatsView-*`、`usage-charts-*` 与 `chat:restore` 的请求起止，不把首屏空骨架当作正文或数据已到。

## 影响范围与下一步

- **共用启动、聊天、笔记**：不改变 SSE 断线恢复、历史分页、笔记保存/CAS；未改的笔记只复用当前页内的干净正文。新文档或他处有改动仍取正文。
- **文件 / Git**：普通文件初开不会再等正文回来才下载 Monaco；没打开文件时仍不加载它。Git 比较的首次 Monaco 模块和仓库状态串行路径未改，准备优化前先分开测 Git 进程、资源下载与文件正文耗时。
- **统计 / 会话详情**：先有统计数值与表格，再补图表；会话详情未点「用量」不会读取逐请求账本。
- **设置 / 终端**：未改实时路径。设置性能页的实现仍位于共用启动资源里，后续可先量包体再拆分；普通 PTY 输出已经走事件流，隐藏与重连恢复不靠轮询输出。终端控制设置页的独立轮询另算。
- **真实公网**：此次没有替换现役 Mica 或修改反代与隧道，也没有测登录后的手机链路。正式生效需按 `agent/build.md` 打包并由用户择机重启。验收时在同一外网设备、相同网络分别测冷启动与热切换，同时验证登录、笔记编辑保存与 SSE；若有静态镜像，校对 hash 与当前桌面版本。不要缓存私有 API 或为资源提速放宽门禁。
