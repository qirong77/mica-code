# 模型图片保护

本地图片、MCP 图片、插件工具图片与恢复的历史图片使用同一份 `prepareImageForApi` 策略。目标是让不可用图片成为模型能处理的工具反馈，而不是把整轮请求变成不可重试的 HTTP 400。

## 处理链路

1. 图片入口识别实际格式和正尺寸，不信任 MIME 声明。PNG 完整解码验证，长边超过 1568 时缩小；JPEG/GIF/WebP 只识别尺寸，不做全量解码或重编码。WebP 支持 VP8/VP8L/VP8X 的尺寸。
2. PNG 源图上限为 16,777,216 像素（Mica 的资源预算，不是模型接口的要求）。在分配与解压前检查；inflate 输出最多为 IHDR 声明的扫描线字节数，阻止压缩体积很小但解压量异常的输入。不支持的 PNG 编码变体可在安全尺寸内透传，损坏的受支持编码拒绝。
3. 最终图片长边上限 8192。PNG 正常缩小后符合上限；其它格式或无法缩小的 PNG 超限时返回裁剪/分段提示。
4. MCP 按原块顺序逐张准备；单张失败替换为说明，其他图文保留。缩小图片前附原始/实际尺寸及查看细节的提示。
5. `PiModelClient` 每次请求在副本中准备 user/toolResult 图片，覆盖旧会话和插件结果。失败只换该图片块，不修改原历史。query 内弱引用缓存已处理块，避免连续工具迭代重复解码；缓存随 query 释放，且不额外持有已从历史移除的源块。
6. 准备前后检查请求字节预算：正文 20 MiB、单张内联载荷 6 MiB，优先保留新图。先限量避免无用解码，后复核覆盖重编码和占位文本的大小。预算不影响工具参数和思考签名。

例如原事故中的 2360 × 32000 PNG 有 75,520,000 像素，超出本机解码预算，直接给模型分段截图提示；不会尝试分配整张图的像素缓冲，也不会把原图继续送给接口。普通细长 PNG 如 10 × 9000 可缩成 2 × 1568，并明确提示细节可能丢失。分段截图由模型依据页面内容继续调用工具完成，宿主不自动生成大量切片。

## Codex 参考

核对版本：OpenAI Codex `1145028ae47e8119955323d38ce34122d418f951`（2026-11-21）。参考仓库为临时克隆 `/tmp/mica-codex-image-study-20261121`。

- [统一请求图片准备](https://github.com/openai/codex/blob/1145028ae47e8119955323d38ce34122d418f951/codex-rs/core/src/image_preparation.rs)：消息附件与工具图片共用准备过程；单图失败换文本占位（`prepare_message_content` / `prepare_tool_output_content`），不会因一张图的准备失败丢掉全部结果。
- [图片工具库](https://github.com/openai/codex/blob/1145028ae47e8119955323d38ce34122d418f951/codex-rs/utils/image/src/lib.rs)：完整解码验证、按长边和 patch 数缩放，并使用最多 32 项 / 64 MiB 的缓存避免重复处理。
- [可选 sanitizer](https://github.com/openai/codex/blob/1145028ae47e8119955323d38ce34122d418f951/codex-rs/utils/image/src/sanitizer.rs)：解码前限制 10,240,000 像素，输入/输出各限 79 MiB，重新编码并处理元数据。
- [功能开关](https://github.com/openai/codex/blob/1145028ae47e8119955323d38ce34122d418f951/codex-rs/features/src/lib.rs)：该版本 `safe_image_decoder` 仍为开发中且默认关闭；`unified_image_budget` 默认启用，但还受模型条件约束。不能把 sanitizer 的限制当作 Codex 默认行为。

Mica 借鉴统一准备、逐图降级、缩放说明、处理缓存和解码资源边界；沿用已有 1568 长边和请求字节预算。未引入 Rust/原生图像依赖，也未照搬 Codex 的 EXIF/ICC、附件上传和原图重放元数据机制。当前非 PNG 只做头部格式/尺寸检查，因此无法保证拦截所有损坏的 JPEG/GIF/WebP；远端接口对这些数据的其他限制仍可能产生错误。

## 验证

针对性测试覆盖 MCP 超长图/坏图/混合图文顺序、恢复历史中的超大图、处理缓存与历史不变、PNG 解压长度与像素限制、三种 WebP 尺寸，以及 pi 四协议的图片发送。普通图片样本必须使用有效编码数据，不使用仅有格式名的 Base64 或校验和损坏的 PNG。
