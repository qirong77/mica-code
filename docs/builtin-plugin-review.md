# 自带插件功能与设计审查

范围：`packages/mica-official-plugins` 登记的 17 个官方插件，以及共享插件宿主、设置页、桌面插件入口。审查包含实现、生命周期、会话归属、持久化、动态配置、失败反馈及已有测试；真实外部服务和操作系统授权需要单独集成验证。

## 共享宿主

- 开启“复用当前会话模型”后，原先保留的独立模型名仍可能影响请求、配置摘要和连接测试。现在三者都跟随当前会话模型，调用方显式指定模型仍有效。
- 正常卸载资源原先正序清理，且一项失败会阻止后续清理。现在按登记逆序释放、收集错误后统一报告；每插件保留实时登记表，也回收 setup 完成后登记的资源。
- 桌面面板、会话菜单、设置页动作缺少统一卸载登记。现在自动绑定插件生命周期，覆盖启动失败与正常关闭。
- 正常取消后台任务原先会留下插件故障状态。现在主动取消不再上报失败。
- 插件模型用量原先在请求结束时才选择当前会话。现在发起时捕获会话与 id；切换后仅把用量追加到原会话，原会话已删除则不重建。
- 桌面会话复制在剪贴板写入失败时仍使用插件提供的“已复制”文案。现在返回明确失败。
- 插件数据读改写缺少版本比较。现在提供 `{ value, version }` 读取与 `writeData(value, { expectedVersion })`，在跨进程互斥下比较并原子写入；冲突由插件重读后重放本次修改。
- 桌面会话标记菜单与 Session Tags 命令原先各自读改写同一份文件。现在两端共用同一把跨进程锁，拿不到锁时明确返回“稍后重试”，不再可能互相覆盖。

## 第二轮：自动压缩、子代理闪烁与长运行

第二轮起点为 `2026-10-31T04:43:06Z`。持续自测在 `05:51Z` 按用户要求停止，**没有完成原定的两小时**；实际连续运行 3,833 秒（约 64 分钟），3,831 轮、356,537 次断言、0 失败，覆盖压缩、锁、调度器和后台心跳。更新后代码另跑 1,677 秒、1,676 轮、157,975 次断言、0 失败。两轮均使用隔离 `MICA_HOME`，不访问外部服务；样本在 `/tmp/mica-plugin-soak-20261031T044306Z/`，复跑脚本为 `scripts/plugin-soak.mjs`。

### 自动压缩

- 原先在迭代结束、最终回答已经产出后检查压缩，会拖慢收尾；现在每次模型请求前检查，压缩结果直接进入本次请求。
- 快速清理原先按固定条数保护尾部，长工具循环里可能删掉刚返回、模型尚未读取的结果。现在保护最近 8 条完整工具配对；模型摘要至少保留最新一轮用户请求，单独超长工具循环不会因“保留最近一轮”而无法压缩。
- 阈值按当前模型上下文窗口计算：快速清理 55%、模型摘要 75%、接近容量 88% 时绕过 30 分钟最小间隔；小窗口模型不会等到固定 200K 才动手。最小间隔只约束同一轮运行中的重复压缩：`turn:before` 记录本轮起点，上一轮压过不拖住新一轮，空闲触发也直接不看它。没有可压缩内容时退避 60 秒，避免每个请求重复扫描。
- 压缩请求携带发起会话、可在 abort 时取消；取消后不写回、不提交缓存。空闲触发也按事件里的 owner 读写设置、计数与 notice，不再误用当前选中的会话。one-shot（`mica exec`）继续不启用自动压缩。
- 同一约 29 MB 工具历史、15 次采样，快速清理中位耗时从约 19.5 ms 降到 3.9 ms；主要去掉了 token 估算时的大字符串序列化与 JS 扫描。

### 子代理区域闪烁

- 根因是 Memory 默认在回答结束后自动整理，整理内部使用宿主子代理；它虽然不属于用户委派，仍被投影成子代理任务，因此没有调用 `agent` 的会话结束时也会闪现子代理 dock。
- 通用能力面新增 `PluginSubagentType.activity: 'delegation' | 'maintenance'`；`mica/subagentTasks/updated` 与 TUI dock 过滤 maintenance，用量和任务记录仍保留，`agent list/read` 仍可查看。
- Memory 的 curator 类型已标记 maintenance。新增 app-server 投影、TaskManager、UI bridge 与 Memory 注册的回归用例。
- **边界**：已定位并修复代码路径，单元与集成投影测试通过；没有在真实桌面窗口里完成“长会话自动整理时观察 dock”的可视复现，重启应用后仍需目视确认一次。

## 保留的产品取舍

- Commit 延续整仓库分析、整仓库提交；是否推送来自设置，未增加文件选择或命令参数。
- Todo 仍属于当前轮次，新轮次不继承旧计划；修复的是多个主会话之间的隔离。
- Memory 保留会话内冻结已注入记忆的行为，避免对话中途更改同一段系统上下文。
- Session Tags 保留固定七个色槽，通过重命名表示分类。
- 排期不同阶段的跨窗口修改会合并，同一阶段的并发修改以最后一次成功保存为准。
