# Mica 远程 Agent 上下文：在 B 上操作 A 的工作区

**状态：第一版已实现（P0–P1 + 只读历史），远程执行尚未开放。** A 是家里的开发机，B 是公司的控制端，R 是已准备的中转机。本文不要求在工作电脑上开放端口、上传项目或部署服务。

**推荐方案：入口做成类似 SSH 的官方插件；连接和执行由 Mica 宿主管理；中转机单独部署。** 在 B 上选中 A 后，输入框应该明确显示 `家里的 Mac / 示例项目`。用户点发送，读文件、改代码、调用工具和保存会话的都是 A。换一台获准的电脑，只是换了操作界面，不是换了一台机器重跑任务。

## 1. 用户实际会看到什么

1. **在 A 上开放一个工作区。** 用户选择一个目录，给它起展示名，勾选允许远程使用的会话和能力。注册设备不等于分享所有项目或已有会话。
2. **在 B 上添加上下文。** 从聊天页选「远程上下文 → 家里的 Mac → 示例项目」，新建或打开 A 的一条会话。B 不需要有这个仓库，也不需要配置 A 的模型密钥。
3. **在 B 上发任务。** 比如“检查示例项目的入口，修正标题，并告诉我改了什么”。A 在授权的工作区执行；B 实时看到运行阶段、允许展示的回答和终态。A 读取源文件，不等于要把源文件发给 B。若用户另点“查看文件片段”，那是一次单独授权的读取。
4. **换设备或账号。** 获得同一授权的账号看到同一条会话、同一个运行结果。只读成员能围观，不能发任务；未获授权的账号连这条目录记录都看不到。

| 此刻的情况 | B 应该显示 | B 发起新操作时 |
| --- | --- | --- |
| A 在线、会话空闲 | 当前会话、在线状态；获准时显示实时正文 | 读当前文件或启动一轮，都由 A 应答 |
| A 在线、会话正忙 | 同一个正在进行的轮次；多个页面可以观看 | 第二个启动请求返回“会话正忙”，不偷偷排队；获准的停止只作用于指定轮次 |
| A 已离线，B 已保存过部分内容 | 显示已保存的历史、保存时间及“非实时”标记 | 读取当前文件、取最新 diff、发任务均报“执行机离线”；绝不改读 B 的同名文件 |
| A 已离线，B 是首次登录的新设备 | 可见获准的目录；仅当历史已另存到 R 且此设备已获解密授权时，才能读那部分历史 | 没有保存过的内容就是不可用，不显示成“空会话” |
| 发任务后中途失联 | 显示“连接中断，执行结果待确认” | 重连后查原任务；不自动重发，不把断线显示为失败或完成 |

这里的“实时”是**在线时实时处理本次请求和订阅的变化**，不是后台镜像整个工作区。A 休眠、Mica 退出或关闭远程开关，都意味着 A 无法再接受新请求。

## 2. 架构与现有项目的分工

```text
B：Mica 聊天页 + Remote Context 插件
       │ 本机 HTTP / SSE（沿用桌面传输）
   B 的宿主客户端 ──出站 HTTPS / WSS──► R：身份、目录、在线状态、路由
                                                        ▲
                                           出站 WSS ────┘
                                          A 的机器级 Worker
                                                  │ 校验授权、选择本地会话
                                          A 的 mica app-server
                                                  │
                                      A 的项目、会话存储、受限工具
```

A 开启“允许远程使用”时，即便没有打开聊天页，也保持一条到 R 的连接，否则 B 无法启动第一轮。B 只在打开远程界面或订阅运行时保持实时连接。多个会话复用机器连接，不为每个文件、工具或 token 创建请求。R 不能以任意 URL、IP、端口或路径为目标做代理。

| 位置 | 已有基础 | 需要新增的职责 |
| --- | --- | --- |
| B 的插件入口 | [Connections](../plugins/connections/README.md) 是地址簿，打开的是另一台运行时的窗口；[SSH 插件](../plugins/ssh/README.md) 是让**当前 Agent** 调远端命令。两者都不是切换整条会话的执行机。 | 新增可停用的官方 `Remote Context` 插件，负责配对、选机、选项目、权限和状态提示；不再维护一份旧连接地址簿，不把路由凭据交给模型。 |
| B 的桌面宿主 | [renderer 传输](../apps/desktop/src/renderer/src/transport.js) 已使用 HTTP + SSE；[chat host](../apps/desktop/src/host/chat.js) 已有恢复和历史分页入口。 | 聊天节点绑定显式目标 `local` 或 `(tenantId, machineId, workspaceRef, sessionRef)`；用适配器把远程投影送到当前页面。草稿、缓存、订阅按目标隔离，切换机器不带走上一台的输入或附件。 |
| A 的机器级服务 | 普通插件按会话装配，[插件生命周期](../agent/plugins.md) 不能保证恰好全机一条连接。 | 由桌面运行时监管一个 Worker（每个用户运行环境一份）；插件通过**通用的宿主服务能力**启停，不在内核写插件名。抢占本机单实例租约；服务重连用新连接代次使旧连接失效。不安装插件关闭后仍存活的后台服务。 |
| A 的会话执行 | [`mica app-server`](../apps/cli/src/cli/runAppServer.ts) 是每会话的 stdio 进程；[执行器](../apps/cli/src/runtime/HeadlessTurnExecutor.ts) 和 [SessionStore](../packages/mica-session/sessionStore.ts) 已处理轮次和本地写锁。 | Worker 只把白名单操作适配到本地会话。确认恢复的会话 ID、工作区和执行策略均匹配后才启动；恢复失败不能退到新会话或进程默认目录执行。历史经投影和分页返回，不传整个快照。 |
| R 中转服务 | 当前仓库有旧 relay 入口链接和探活约定，但它们不表达账号、设备、工作区和会话授权。 | 单独服务处理登录、设备登记、授权目录和连接路由；初期一个进程和 SQLite 即可。无需安装 Agent、挂载项目或持有模型密钥。 |

**不能把现有 `/api/invoke`、`/api/events`、分享页或 app-server 的全部 RPC 透传到公网。** 现有[远程访问判定](../apps/desktop/src/host/remote-access-core.js)保护的是完整运行时入口；分享视图并不是逐会话的 API 权限边界。新入口有独立鉴权和操作白名单，不继承分享 cookie、旧链接 token 或“来自回环地址即本机”的信任。

## 3. 什么会经过中转机，什么不会

**工作电脑首先是授权问题，不是传输格式问题。** B 发出的提示词可能包含公司代码，A 的回答也可能引用源码。没有获准的目标地址、数据类别和设备范围，就保持本地，不登记、不发送。HTTPS、应用层加密和限流用于保密与控制资源，不用于规避公司审计；如果组织要求检查的链路与某模式不相容，就不启用该模式。

| 数据 | A / B / R 如何处理 |
| --- | --- |
| 路由目录 | R 可保存不透明的机器、工作区和会话引用、授权关系、手填别名、最后确认的状态与时间。只登记显式分享的条目。**不直接用 Mica 的现有会话标题**：其[默认标题逻辑](../apps/cli/src/session/SessionController.ts)可能取自用户消息。未起别名就显示中性编号。 |
| 在线问答 | B 的输入经 R 到 A；A 将按策略可显示的回答及固定运行阶段传回 B。R 默认不持久化正文。B 不自动附带本机选区、剪贴板、附件、`@文件` 展开结果或环境信息。手工粘贴的文本仍是外发数据。 |
| 工作区内容 | 文件、Git 对象与原始 diff 留在 A。默认只回固定状态或变更计数；有独立授权且用户主动查看时，可回有界的文本预览。**屏幕上能读到的片段已经跨机传输**，不因它是 JSON 而例外。没有项目打包、文件上传/下载、二进制附件或目录同步接口。 |
| 内部上下文 | 不直接转发完整 session JSON、系统提示词、推理过程、原始工具参数/结果、终端流、环境变量、Cookie、凭据或插件私有状态。`item/completed` 也要按类型构建白名单字段，不能只过滤增量而漏掉最终消息。 |
| 模型调用 | 工具在 A 执行；若 A 使用外部模型，获准的上下文会从 **A 发往模型服务商**，这是独立于中转机的另一条数据流。要求源码不出 A 时，只能使用符合该要求的本地推理/工具策略；隐藏 B 的文件预览不够。 |

**隐私设置分三步，不用一个“开启同步”包揽：**

- **允许登记目录**：远程功能初始关闭。仅批准目录时，只发送上表的固定元数据，不发自动摘要、自由文本或文件；不能以“仅元数据”名义发送可引用源码的模型回答。
- **允许实时访问**：逐工作区开启可显示问答、可发任务、可预览文本等独立能力。实时可看不是持久保存许可；默认会话断开后不在 R 留正文。
- **允许保存历史**：可以只在 B 保存已显示且准许留存的问答；也可以另行批准 R 保存筛选后的**加密历史事件**，供其他获准设备使用。两者分别开关。历史只含已发布问答、轮次终态和时间，不含文件预览、工具输出或实时草稿；不默认回填已存在的所有会话。

**离线历史有来源、版本和期限。** B 记录 `source / historyRevision / savedAt / expiresAt`；读取时显示“本机已保存”或“中转机已保存”，不冒充实时结果。B 缓存按账号和设备加密，密钥进系统安全存储；没有可用安全存储就只用内存。A 离线但 B 能连 R 时仍检查当前授权；B 自身也离网时默认不解锁受管正文。A 改写/删除历史时发布新版本或删除标记，旧页失效；停用保存时停止新增，并提供单独的清除操作。备份受同一到期策略约束。撤权不能收回对方已经看过、复制或截屏的内容。

## 4. 身份、加密和执行权限

1. **账号不等于设备授权。** 推荐接组织批准的 OIDC 身份源，按租户隔离。A 本地选定工作区，B 登录后通过短期、单次配对流程，由 A 的所有者确认设备、目标和权限。长期凭据不放在 URL、不写插件普通设置、不需要用户复制 token。第二个账号需要显式邀请；设备丢失可独立撤销。
2. **明确谁能解密。** 所有网络链路必须走证书验证的 HTTPS/WSS。TLS 若终止在 R，单靠 TLS，R 就能读正文。本文建议：有正文的模式须采用组织批准、经审查的**设备间认证加密协议**，由登记过的端点加解密，R 只转发密文。配对时通过已有受信设备或组织设备身份核对对端公钥，不能仅信 R 临时返回的公钥。协议库负责握手、重放保护、密钥轮换；不自创算法或拼接密码原语。若尚无获准方案，先交付目录，不降级传正文。R 仍可见目标设备、时序、在线状态和流量大小。
3. **保存密文需要独立授权。** 可选历史按会话及密钥代次加密，读取既要有效授权，也要有分发给该设备的历史密钥。新设备没有密钥时明确提示“需授权设备在线确认”。撤权立即停止路由、订阅和历史下载，轮换之后的密钥；注销时清对应本机密钥和缓存。R 不能靠重置登录口令解密历史。
4. **R 粗查，A 细查。** R 按账号、设备、目标、授权版本及有效期检查目录访问、订阅和路由；它看不到密文里的方法和路径。A 校验已配对设备身份、请求绑定、授权版本、会话归属，再对**具体操作**校验。授权失效时应切断已开的订阅，不能只把按钮变灰。

| 权限 | 允许的操作 | 不隐含的权限 |
| --- | --- | --- |
| `session.view` | 查看已授权目录、状态及策略允许的问答 | 发送、中止、文件读取、保存历史 |
| `turn.operate` | 在指定会话发起/中止受限轮次 | 改模型凭据、扩大工具集、直接执行任意 shell |
| `workspace.preview` | 在指定工作区查看获准文件的有限文本片段 | 目录下载、写文件、终端、查看其他会话 |
| `history.save` / `history.readSaved` | 分别允许保存或取回指定会话的历史投影 | 备份整个工作区、读其他账号的缓存 |
| `grants.manage` | 所有者登记、邀请、撤权和清理 | 自动解密另一个账号的旧历史 |

**发任务本身就是执行权限。** 只在 RPC 层禁掉 shell 不够，用户仍可在提示词里要求 Agent 调工具。A 应在可信执行器里，对每次工具调用、插件、MCP、子代理和后台任务施加同一套上限：`远程授权 ∩ A 的工作区策略 ∩ 会话原有能力`。默认不开放通用终端、SSH、桌面控制、任意网络工具或权限管理。需要写项目时，用受限系统身份/沙箱只开放获准工作区，凭据、其他项目和宿主控制接口不可达。现有 [app-server 的 approval/sandbox 参数不是系统沙箱](./headless-design.md)。不能复用一个权限更高的本地宿主冒充隔离；无法落实执行边界时只提供目录和获准的只读历史，**不开放 `turn.operate`**。

## 5. 远程协议 v1（拟议，不是现有 API）

控制面用 HTTPS 做登录、配对、撤销和目录分页。实时面通过 WSS 在 B 与 A 之间路由。外层只放版本、目标及设备不透明引用、连接/密钥代次、必要的关联信息和长度；业务方法、提示词、相对路径和结果在加密体内。双方在处理正文前校验版本、授权、过期时间和长度；对端身份、目标和会话绑定不能被换用。

| 方法 | 谁应答 | 语义与边界 |
| --- | --- | --- |
| `directory.list` | R | 分页返回该账号获准的机器、工作区和会话索引；`lastKnownAt` 和当前可达性分开。A 在线可更新，离线不假装刷新。 |
| `session.create` / `session.attach` | A | 在授权工作区创建受限会话，或附着已有会话。创建须有写授权和幂等键；附着只建立订阅，不新建会话、不开新轮次。 |
| `history.page` / `history.savedPage` | A / 本机缓存或 R | 前者读当前投影，后者读已保存的指定版本；响应标明来源、版本和时间，不用缓存冒充前者。 |
| `turn.start` | A | 只收用户明确发送的文本和目标；A 返回受理回执，**不是完成通知**。不接受调用方传工具清单、绝对 cwd、环境或 provider 配置。 |
| `turn.status` / `turn.interrupt` | A | 用 `requestId` 找回丢失的回执，或用 `runRef` 查状态；中止必须匹配当前的 `runRef`，不能打断之后的新一轮。 |
| `workspace.preview` | A | 显式读取一个许可文件的有限文本选区；需单独文件权限并受出站策略约束。A 离线时失败。 |
| `session.detach` | A / R | 取消此查看者订阅；关页面不等于停止 A 上已接受的任务。 |

**一个发送例子**（加密前的逻辑形状，示例值不是凭据）：

```json
{"v":1,"op":"turn.start","requestId":"r1","workspaceRef":"w1","sessionRef":"s1","text":"检查示例项目的标题"}
```

A 先记录本次请求，再转给本地宿主；B 拿到 `{ "requestId": "r1", "runRef": "u1", "state": "accepted" }`。之后依次收到 `turn.started`、按策略筛选的 `turn.phase` / `message.delta`、`message.final` 和 `turn.finished`。事件来自现有 [CodexProjector](../apps/cli/src/runtime/CodexProjector.ts) 等本地事件的**白名单投影**，不是原始 stdio 的复制。终态区分 `completed / aborted / error`；`unknown` 表示观察者尚不能确认，不是 A 的成功或失败终态。首版不做远程 `steer`、任意命令、直接编辑器写回；要加这些能力须各自设计权限和幂等语义。

**文件预览不是下载。** B 提交工作区引用、相对文件名、明确选区及可选的预期版本。A 在实际打开文件时确保目标仍是获准根目录内的普通文本文件，拒绝路径越界、符号链接逃逸、特殊设备、敏感路径和二进制。回复带 `revision` 以及 `truncated`；版本变了就提示刷新。大文件不自动续取，不将完整文件或超限内容拆成许多预览请求；政策不允许显示源码就没有这个能力。

## 6. 断线、重连和多端并发

### 6.1 一次点击不能变成两次执行

- B 每次显式点击发送生成 `requestId`。A 按 `(tenant, actorDevice, sessionRef, requestId)` 唯一登记，保存请求指纹、稳定的 `runRef`、状态和有效期。**落盘占位先于调用执行器**。同一 ID、同一内容只能查原回执；同一 ID、不同内容报 `conflict`。去重记录保留期必须长于请求有效期。
- A 的本地 turn lease 才是会话唯一写入者的依据，不在 R 建一套分布式会话锁。远程启动须在本地取得租约的路径上实现“忙则拒绝”，不能先读一个空闲标记，再走会自动排队的入口。多个客户端可看同一轮，本地窗口和远程窗口抢同一轮时只有一个能写。
- A 的 `turn/started` 发出后，把真实 `turnId` 与 `runRef` 关联。发送中断或回执丢失时，B 只查 `turn.status(requestId)`。若 A 恰好在“已占位、工具可能已执行、未记终态”的窗口崩溃，无法从本地证据确认就返回 `unknown`；不自动补执行，也不承诺任意工具副作用“恰好一次”。用户核对后可显式发起**新的**任务。
- **已知离线且请求未转发**才报告 `offline`；可能已经送达时报告 `unknown`。R 不保存待上线执行的写请求。B 断开后，A 可按仍有效的本地授权完成已接受的轮次；撤权与关页面不同：A 收到撤权立即拒绝新操作、停止交付并尝试中止关联任务。分区期间依赖短期授权到期阻止继续发起受限工具；已产生的修改不能靠撤权回滚。

### 6.2 只补显示，不重放命令

每个订阅有 `streamEpoch + seq`，每份历史投影有 `historyRevision`。B 按序号去重，重连携最后游标。A 的有界短期缓冲可覆盖缺口时，只补业务事件；缓冲过期、A 重启、会话被编辑/压缩或权限变更时，返回 `resync_required`。B 重新读**获准的一页历史 + 当前运行态**，合并读取期间的新事件；不能拼接旧版本或回退到完整 session JSON。现有桌面 SSE 会断线重读，但不是可靠队列，不能假设它已经能跨机器补帧。

A 的连接代次变更后，R 移除旧订阅并拒绝旧连接的请求；A、B 重验身份与权限后再附着。仅 B 断线不能推断 A 停机。区分界面文案：“A 离线”“无法连接中转机”“任务结果未知”“会话正忙”“权限已撤销”“内容未保存/已过期”。

## 7. 控制请求大小、频率和留存

以下是**容量测试的起始预算**，不是已测性能，更不是为了贴近监控阈值。配置只能在部署批准的上限以内收紧；A、B 和 R 都要执行各自能验证的限制。

| 对象 | 首版建议 | 超出预算时 |
| --- | --- | --- |
| 单条业务消息 | 密文及编码后的整条消息 ≤ 64 KiB；历史按消息边界分页，单页正文 ≤ 32 KiB；文件预览单次 ≤ 8 KiB | 拒绝或显示“内容过大，仅本机可见”；不换协议、不把整份内容切碎补传 |
| 在线事件 | 只向获准订阅者推送变化；短文本和重复进度约 250 ms 合并一次，可靠终态优先；无需流式正文时只发阶段和最终结果 | 慢客户端合并/丢弃临时进度，标明需重读；不无限积压，不因此重跑工具 |
| 空闲和重连 | 每台已开启的执行机一条 WSS；例如 30 秒保活、连续约 90 秒无消息判不可达，断开可即时更新；无订阅不轮询文件或上传历史 | 服务明确返回退避时间；受限或撤权就停，不换域名、连接或账号继续发 |
| 总量 | 同时限制设备/工作区的请求数、并发读取、累计出站字节和 R 的存储配额；初期每设备最多 4 个并发只读请求，生产限额经压测和审批确定 | 返回 `rate_limited`、`payload_too_large` 或 `quota_exceeded`；超限写请求不入执行队列 |

R 默认只保存目录，不保存正文、文件或断线命令。可选历史启用前必须展示保留时间、配额、谁可以读取和如何删除；未设置 TTL/配额就不启用。A/B 日志只保留不透明关联 ID、固定操作和结果码、耗时、大小；R 只记可见的连接/路由元数据。错误日志、代理访问日志、诊断上报、备份也遵守同一边界，不复制正文、路径或令牌。

## 8. 代码与存储落点（拟新增）

| 模块 | 实现大纲 |
| --- | --- |
| `packages/mica-remote-protocol/` | 定义请求/响应/事件、协议版本、大小限制、投影类型、游标和错误码。纯协议不依赖 UI、会话磁盘或应用；密码库通过受控适配器接入。 |
| `plugins/remote-context/` | 官方清单、开关/配对动作、侧栏或输入框上下文选择器、设备撤销、缓存和保留策略提示。插件不获取私钥、直接操作 SessionStore 或注册供模型切机的工具。 |
| `apps/desktop/src/host/`、`apps/cli/src/runtime/` | 桌面宿主管理 B 客户端和 A Worker 的生命周期；抽出通用会话适配器，复用本地执行器、租约和事件。A 有独立的远程授权映射和请求回执账本，不把路由代码塞进 Agent 推理循环。B 用宿主的私有缓存，不污染本地可恢复的会话目录。 |
| `apps/relay/`（独立构建部署） | 认证、设备公钥、工作区/会话授权、目录、在线连接表、限流、可选密文历史的保留与删除。v1 用单个 JSON 文件加原子写存设备/授权/目录（量很小），在线 socket 只在内存，服务重启后靠设备重新注册，不能把盘上的 `online=true` 当作事实；设备量上来再换 SQLite。 |

最少的数据实体：R 上的 `devices`、`grants`、`directory_entries`（含 `asOf` 和删除标记），以及可选的 `history_ciphertexts(sessionRef, revision, eventId, keyEpoch, expiresAt, size)`；A 上的 `published_contexts`（不透明引用 → **仅本机知道的**目录/会话 ID）和 `request_receipts`；B 上的 `saved_views`（设备/账号/目标、授权版本、保存时间、游标、加密内容）。各自的数据由各自的所有者写入；**R 的目录是索引，不是可以覆盖 A 会话的备份**。

插件关闭、设备注销或退出应用时，宿主停止本服务的订阅、重连、计时器和自有子进程，不杀用户独立启动的本地会话。将来若要做无桌面常在线 Worker，应是用户显式启动和停止的入口，不借某个聊天插件偷偷常驻。

## 9. 开发顺序与验收

| 阶段 | 可交付的改动 | 过关条件 |
| --- | --- | --- |
| **P0：协议和可靠性基线** | 定义边界、威胁模型、协议类型、投影和假中转机；用合成数据做断线和重复投递测试。 | 无网络部署也能验证：未知方法/超限/失效授权拒绝；回执丢失不产生第二次执行。 |
| **P1：选择机器，不传正文** | 机器级 Worker、登录和设备配对、授权目录、上下文选择器、状态显示与撤销。 | 两个不同的授权账号看到同一条目录；第三个看不到。无聊天页也能选 A；A 下线后目录标旧；关闭开关后不再连接。 |
| **P2：在线只读与 B 端已保存历史** | 通过批准的加密方案传输白名单历史页、运行状态；增加版本、游标、受控本机缓存和删除。 | A 离线时，B 只能读准许且已保存的页；从未保存的显示不可用。relay 数据库、代理和应用日志里找不到测试正文。 |
| **P3：第一个可用的远程开发版本** | 在受限执行环境实现启动、查询、中止；接入持久回执、会话锁、即时事件及可选的授权文本预览。 | B 发任务，只改 A 的示例项目；B 可看实时进度。忙时拒绝；A 离线后读文件/发任务失败。断在写入后、响应前，重连不重复写入。 |
| **P4：可选跨设备离线历史** | 密文事件保留、按设备授权读密钥、TTL/配额/删除、撤权换代。Git diff 预览、直接编辑、交互终端不随此阶段默认开放。 | A 下线时另一台已获密钥的设备可读获准历史；新设备无密钥不能读。撤权或过期后不得继续从 R 取，不能读到当前文件。 |

**集成测试搭两端，不拿真实办公数据做验证。** A 和 B 各用隔离的 `MICA_HOME`、桌面用户数据和端口；测试仓库、模拟模型和本地测试 R 全部分开。至少覆盖：

- **运行位置**：在 A 和 B 都创建同名但内容不同的文件。远程问答/预览只反映 A；A 下线时操作明确报错，B 的文件始终未被读取或修改。A 的一次真实测试写入有可核对的次数。
- **权限与泄露**：观察者、操作者、无权账号分别尝试订阅/启动/读取；撤权时保持页面打开。给模拟密钥、未发布项目、自动标题、原始工具输出放不同标记，验证它们不出现在远程投影、缓存或日志里；恶意提示不能放开本地工具或越界读文件。
- **副作用与恢复**：同一 `requestId` 重复到达、并发本地轮次、启动回执丢失、A 在执行前后崩溃、迟到的停止请求、R 重启。核对执行器的实际启动数，不用 UI 出现一个气泡代替验收。
- **历史与负载**：漏帧/重连和压缩改写同时发生，只展示当前版本；无历史副本时不伪造数据。长回答、过大文件、慢订阅者、多窗口受限于预算；停用后没有连接或后台上传。

**建议先做 P0–P1。** 这两步就能演示“B 选中 A、不同账号看到同一条获准会话、A 离线显示最后状态”，不用任何真实正文。进入 P2 前先确定哪些问答允许到达 B、是否准许在 B 留存；进入 P3 前验证 A 的执行隔离；只有确实需要“换一台新电脑，A 关机也能读旧历史”才建设 P4。

### 尚未实现

- **`turn.operate`**：远程发任务、中止、文件预览都还没开放。必须先有受限工具集、执行隔离、请求回执去重（`requestId`）和本机 turn lease 的“忙则拒绝”，不能直接透传现有 `app-server` 的全部 RPC。
- **桌面插件入口**：v1 是 `mica remote` 命令行；输入框里的机器选择器和会话页尚未接入。
- **账号与多租户**：v1 用 relay 邀请码 + 设备配对，没有 OIDC / 组织身份。“不同账号看到同一会话”目前等价于“多台设备被同一台执行机授权”，还不是账号级共享。
- **前向保密与密钥轮换**：v1 是静态 X25519 + 每次运行有效的配对码；设备长期密钥泄露会暴露历史密文。正式版应换成经审查的会话协议，并按会话代次轮换。
- **R 上保存加密历史**：v1 只有控制端内存/终端输出，没有离线历史副本；A 离线时只能看 relay 目录缓存，读不到旧正文。
- **执行隔离与数据外发审批**：E2E 只保护传输，不改变“哪些内容允许离开工作电脑”的组织规则。
